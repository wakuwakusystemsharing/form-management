# 選択肢ごとの「送信時の追加メッセージ」/ 予約カスタム項目のタグ 実装設計

作成日: 2026-10-28

## 目的

- アンケート / 予約フォームの選択肢（ドロップダウン・単一選択・複数選択）に「設定」ボタンを付け、
  その選択肢が選ばれた状態で送信されたとき、送信内容に続けて **固定テキストを LINE トークへ追加で送る**。
  例: 「A ボタン」を選んで送信 → アンケートの内容 + A 用の案内文 が届く
- 予約フォームのカスタム項目の選択肢に、アンケートと同じ **「タグ」**（予約した顧客へ自動付与）を追加する

## LINE 側の制約（最初に決めたこと）

- LIFF `liff.sendMessages()` は **1 回の呼び出しで最大 5 通**。
  本文（1 通）+ 基本情報の「2 通目のメッセージ」（最大 1 通）を含めた合計なので、選択肢の追加メッセージに使えるのは **最大 3〜4 通**
- 方針（利用者の選択）
  - 上限超過は **保存時に制限**（同時に選ばれうる最大の組み合わせを数え、5 通を超える設定は保存できない）
  - 1 選択肢につき **1 通**（ON/OFF + 文言。`second_message` と同じ形）
  - 「設定」は 質問本体の選択肢 / 追加質問の選択肢 / 予約フォームのメニュー・サブメニュー・オプション すべてに付ける
  - 予約カスタム項目のタグは **予約に紐付いた顧客**（LINE ユーザー ID → 電話番号 の順で特定）に付ける

## データ

| 場所 | フィールド |
| --- | --- |
| `SurveyQuestionOption`（質問・追加質問の選択肢。入れ子含む） | `extra_message?: OptionExtraMessage` |
| `config.custom_fields[].options[]` | `extra_message?` / `tags?: string[]` |
| `AdditionalQuestion.options[]`（メニュー・オプション・カスタム項目の追加質問） | `extra_message?` |
| `MenuItem` / `SubMenuItem` / `MenuOption` | `extra_message?` |

`OptionExtraMessage = { enabled: boolean; text: string }`（`src/types/form.ts`）。OFF かつ空文言なら編集 UI が `undefined` に戻す。

## 純粋ロジック `src/lib/extra-messages.ts`

- `LIFF_MAX_MESSAGES = 5` / `EXTRA_MESSAGE_MAX_LENGTH = 1000`
- `resolveExtraMessage(raw)` … ON かつ文言ありのときだけトリム済み文言
- `capLiffMessages(texts)` … 重複除去 + 5 通に収める（あふれた分は最後の 1 通に空行区切りで連結。送信時の保険）
- `countSurveyMaxLineMessages(config)` / `countReservationMaxLineMessages(config)` … 同時に選ばれうる最大数
  - 単一選択 / ドロップダウン = 最も多い選択肢 1 つ、複数選択 = 全選択肢の合計
  - 追加質問（入れ子）は親の選択肢の下に加算
  - 予約: メニューは「カテゴリーまたぎ複数選択」なら上限数ぶんの多いメニュー、それ以外は最も多いメニュー 1 つ。
    メニューのオプションは全部、サブメニューは最も多い 1 つ、カテゴリー共通オプションは全部（単一選択モードでは最も多いカテゴリー 1 つ）
  - 非表示（表示トリガー）の質問 / 項目も表示されうるものとして数える（保守的）
- `validateLiffMessageLimit(count)` → 日本語のエラー文 / `validateFormExtraMessages(config, 'survey' | 'reservation')`
- `EXTRA_MESSAGE_RUNTIME_JS` … 静的 HTML に埋め込む `xmResolve` / `xmCapMessages`

## 生成 HTML

- アンケート `static-generator-survey.ts`: `svCollectExtraMessages(hiddenIds)` が表示中の質問で選ばれている選択肢を
  `svSelectedValues(qid, path)` で入れ子までたどって文言を集める。送信は
  `[本文, 2 通目?, ...追加] → xmCapMessages → liff.sendMessages`
- 予約 `static-generator-reservation.ts`: `BookingForm.collectExtraMessages()` が `getSelectedOwnerIds()`（メニュー / オプション）、
  選択中サブメニュー、`state.customFields`（カスタム項目・追加質問）から集める。非表示のカスタム項目・隠れている追加質問は数えない。
  Web 予約フォーム（LIFF なし）は従来どおり送らない
- 既存の `second_message` の挙動は変更なし（追加メッセージは 2 通目の後ろ）

## 保存時の検証

- クライアント: `FormEditModal` の「保存」「更新」「更新して他のフォームにも反映」の前に `checkExtraMessageLimit()` → 超えていればトーストで止める
- サーバー: `PUT /api/forms/{id}` / `PUT /api/surveys/{id}` が `config` を受け取ったとき同じ判定で 400

## 予約カスタム項目のタグ

- `src/lib/reservation-tags.ts` `collectReservationCustomFieldTags(config, customer_info.custom_fields)`（選択肢の `value` / `label` 一致。追加質問の選択肢は対象外）
- `src/lib/reservation-tags-apply.ts` `applyReservationCustomFieldTags()`（サーバー専用。`findCustomerByLineOrPhone` → `mergeCustomerTags` → `updateCustomer`）
- `POST /api/reservations` の来店履歴作成の直後（local / Supabase 両方）に呼ぶ。失敗しても予約は成功扱い

## 編集 UI

- 共通部品 `src/components/FormEditor/OptionExtraMessageEditor.tsx`（トグル + テキストエリア + 文字数）。`optionSettingsButtonLabel()` で「設定(N)」
- アンケート `SurveyQuestionEditor` / `SurveyFollowUpEditor`: 「追加質問」の右に「設定」→ 下にパネル（`allowExtraMessage` prop。抽選の事前質問は false）
- 予約 `MenuStructureEditor`
  - カスタム項目の選択肢: 「追加質問」の右に「設定」→ モーダル（追加メッセージ + タグ）
  - 追加質問の選択肢（`AdditionalQuestionsEditor`）: 「設定」→ 下にパネル
  - メニュー / オプション / サブメニューの編集モーダル: 「送信時の追加メッセージ」カードを対応時間設定の上に追加
- 「更新して他のフォームにも反映」: メニュー構成 / カスタム項目のセクションに含まれてそのままコピーされる
