# 顧客管理 カルテ機能 実装設計書（第 1 弾: 注意事項・アレルギー・タグ + 次回への申し送り）

作成日: 2026-09-04 / 対象: `docs/顧客管理_カルテ機能提案.md` の **案 1** と **案 4** / 実装ブランチ: `feature/customer-chart-phase1`

---

## 1. この資料について

提案書のうち「導入しやすく効果が早い」2 案を 1 つの設計にまとめたものです。

| 案 | 内容 | DB 変更 |
|---|---|---|
| 案 1 | アレルギー・既往歴（注意事項）・タグ・希望連絡手段を顧客詳細の最上部に表示し、編集フォームで登録できるようにする。タグは一覧にも表示し、検索・絞り込みに使える | なし（列は既存） |
| 案 4 | 来店記録ごとに「次回への申し送り」を残し、次回来店時（顧客詳細を開いたとき）に最上部の帯で表示。「確認済み」で消える | `customer_visits` に列 3 つ追加 |

対象外（第 2 弾以降）: 施術記録の入力シート（案 2）、写真（案 3）、テンプレート（案 5）、対応履歴（案 6）、お客様への共有（案 7）

## 2. 画面設計

### 2-1. 顧客詳細（既存の全画面シートに 2 つの帯を追加）

```
┌──────────────────────────────┐
│ ‹ 戻る       顧客詳細        ⋯  │
├──────────────────────────────┤
│ ◯ 山田 太郎            [VIP]   │  ← 既存
│   📞 090-…   ✉ …   🎂 1/15     │
│   🏷 指名:田中  平日希望  妊娠中 │  ← 案 1: タグ（最大 6 個。タップで一覧をそのタグで絞り込み）
│   💬 希望連絡: LINE             │  ← 案 1: 希望連絡手段（登録時のみ）
├──────────────────────────────┤
│ ⚠ アレルギー                    │  ← 案 1: 赤系の帯（登録があるときだけ。未登録は出さない）
│   ジアミン、ラテックス            │
│ ⚠ 既往歴・注意事項               │
│   頭皮が敏感。刺激の弱い薬剤で    │
├──────────────────────────────┤
│ 📝 前回の申し送り（9/1・田中）     │  ← 案 4: 黄色の帯。未確認の最新 1 件だけ
│ 次回はトリートメントを提案。       │
│ 前髪は切りすぎない。   [確認済み]  │
├──────────────────────────────┤
│ 来店 12回 │ ¥86,000 │ 初回 │ 最終 │  ← 既存
├──────────────────────────────┤
│ 予約(3)  来店(12)  抽選(1)  LINE   │  ← 既存
│ ┌──────────────────────────┐ │
│ │ 9/1 10:00          ¥12,000 │ │
│ │ カット＆カラー              │ │
│ │ 📝 次回はトリートメントを提案 │ │  ← 案 4: 来店カードに申し送りを表示
│ │            [申し送りを編集]  │ │  ← タップでその場で編集（テキスト + 担当）
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

- アレルギー・既往歴は**登録があるときだけ**帯を出す（毎回「登録なし」を見せるとノイズになる）。編集フォームからは常に入力できる
- 申し送りの帯は「未確認（`acknowledged_at` が null）の最新 1 件」だけ。「確認済み」を押すと `acknowledged_at` が入り、帯は消える。過去の申し送りは来店カードにそのまま残る
- 来店カードの「申し送りを編集」はカード内で textarea を開く（全画面シートは使わない）。保存でカードに反映、帯も更新
- 来店記録が 1 件も無い顧客は、申し送りを書く場所が無いため、「来店記録がありません」の下に「来店を記録すると申し送りを残せます」と案内（来店記録の手動作成は第 2 弾）

### 2-2. 編集フォーム（既存の `CustomerForm` に 1 セクション追加）

```
  ── 安全のための情報（お客様の同意を得て記録してください）──
  アレルギー          [ ジアミン、ラテックス                ]
  既往歴・注意事項     [ 頭皮が敏感。刺激の弱い薬剤で         ]
  希望連絡手段        ( LINE ▾ )   ← 未選択 / LINE / 電話 / メール / 連絡不要
  タグ               [指名:田中 ×] [平日希望 ×]  [＋ タグを追加     ]
                     よく使うタグ: 妊娠中  猫アレルギー  初回  紹介
```

- タグ入力: テキスト + Enter / 「追加」で追加、× で削除。候補（よく使うタグ）は **この店舗の顧客に付いているタグの使用回数上位 20 件**（新 API）。候補をタップで追加
- タグの正規化: 前後の空白を削除、全角スペースを半角に、重複を除去、1 タグ 30 文字・1 顧客 20 個まで
- 「安全のための情報」セクションの見出しに同意の注記を固定表示（要配慮個人情報の取得は本人同意が必要）

### 2-3. 一覧

- 顧客カード（スマホ）と行（PC）にタグを最大 2 個 + 「+N」で表示
- 検索欄の文字列がタグと**完全一致**する顧客もヒットする（部分一致は PostgREST の配列検索で表現できないため）
- `?tag=xxx` の絞り込みに対応（顧客詳細のタグをタップ → 一覧に戻ってそのタグで絞り込み）。絞り込み中はチップ列の先頭に「🏷 指名:田中 ×」を表示

## 3. データ構造

### 3-1. 既存列（案 1。変更なし）

| 列 | 型 | UI |
|---|---|---|
| `customers.allergies` | TEXT | 編集フォーム / 詳細の帯 |
| `customers.medical_history` | TEXT | 同上（表示名は「既往歴・注意事項」） |
| `customers.preferred_contact_method` | TEXT | 値は `line` / `phone` / `email` / `none`（API で検証） |
| `customers.tags` | TEXT[] | 編集フォーム / 詳細 / 一覧 / 検索 |

### 3-2. 追加列（案 4）

```sql
-- supabase/migrations/20260904100000_add_visit_next_note.sql
ALTER TABLE customer_visits ADD COLUMN IF NOT EXISTS next_visit_note TEXT;                     -- 次回への申し送り
ALTER TABLE customer_visits ADD COLUMN IF NOT EXISTS next_visit_note_by TEXT;                  -- 書いた担当者名（任意）
ALTER TABLE customer_visits ADD COLUMN IF NOT EXISTS next_visit_note_acknowledged_at TIMESTAMPTZ; -- 確認済みにした日時
CREATE INDEX IF NOT EXISTS idx_customer_visits_customer_note
  ON customer_visits (customer_id, visit_date DESC) WHERE next_visit_note IS NOT NULL;
```

「帯に出す申し送り」= その顧客の来店記録のうち `next_visit_note` があり `next_visit_note_acknowledged_at` が null のもので、`visit_date`（同日なら `created_at`）が最新の 1 件。判定は `src/lib/customer-chart.ts` の `pickPendingNextVisitNote(visits)`（純粋関数。テスト対象）。

## 4. API

| メソッド / パス | 内容 | 認可 |
|---|---|---|
| `PATCH /api/stores/{storeId}/customers/{customerId}` | 既存。`allergies` / `medical_history` / `tags` / `preferred_contact_method` は既に許可済み。**追加**: `tags` の正規化（配列でなければ 400、30 文字 / 20 個の上限）、`preferred_contact_method` の値検証 | 既存 |
| `GET /api/stores/{storeId}/customers?tag=` | **追加**: タグ完全一致の絞り込み。`search` はタグ完全一致もヒット | 既存 |
| `GET /api/stores/{storeId}/customers/tags` | **新規**: 店舗の顧客に付いているタグを使用回数順に最大 50 件 `{ tags: [{ tag, count }] }` | `authorizeStoreAccess` |
| `PATCH /api/stores/{storeId}/customers/{customerId}/visits/{visitId}` | **新規**: `{ next_visit_note?, next_visit_note_by?, acknowledge?: true }`。`acknowledge` は `acknowledged_at = now()`。申し送り本文を変更したら `acknowledged_at` は null に戻す（新しい申し送りとして再表示） | `authorizeStoreAccess` + 顧客が店舗に属するか + 来店記録が顧客に属するか |

顧客詳細 GET（既存）が返す `visits` に新列が含まれるため、取得 API の変更は不要。

## 6. 表示制御との関係

- 申し送りの帯と来店カードの申し送りは「顧客詳細に予約履歴・来店履歴・統計情報を表示」（`customer_reservation_history`）が OFF の店舗では出さない（来店履歴が見えないのに申し送りだけ出るのは不自然なため）
- 注意事項・アレルギー・タグは常に表示（安全情報のため表示制御の対象にしない）

---

## 7. 注意点

- アレルギー・既往歴は個人情報保護法の要配慮個人情報にあたり得る。編集フォームに「お客様の同意を得て記録してください」を固定表示。プライバシーポリシーへの追記は運用側で対応（本設計の範囲外だが、リリース前に確認）
- 顧客 CSV 出力は現状存在しないため、今回は対象外。将来追加するときは要配慮情報を既定で除外する
- タグに個人を特定できる情報（電話番号など）を入れないよう、候補の説明に注記
