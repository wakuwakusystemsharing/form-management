# 旅館（宿泊施設）向け予約フォーム 実装設計

作成日: 2026-10-23 ／ 更新日: 2026-10-27（v3: 「先に作っておき、ヒアリング当日に設定画面で入力するだけ」にするため設定項目を汎用化）
状態: 第 1〜5 段階 実装完了（2026-10-27）。残り: staging へのマイグレーション適用 → 実機確認（第 6 段階）

## 目的
1 部屋だけの宿泊施設（Airbnb のような運用）が、LINE / Web の予約フォームから「チェックイン日〜チェックアウト日」で予約を受けられるようにする。

## 進め方の方針（2026-10-27 決定）
- **施設の回答を待たずに先に作る。** ヒアリングで出てくる回答は、無理なもの（部屋タイプ別在庫・決済・泊数パック料金・見積もり方式）を除き **すべて設定画面で入力できる** ようにしておく。ヒアリング当日は担当者が画面に入力するだけ
- そのため料金・人数・休業・キャンセル料・受付期限・チェックイン時刻は、固定の形ではなく「一覧を店舗が作る」形で持つ
- テンプレート「宿泊（1 部屋）」の初期値には、いま分かっている内容（1 名 14,000 / 2 名 20,000 / 3 名 26,000、0〜5 歳無料、最大 7 泊、12 か月先まで、前日 12:00 まで受付、7 日前まで無料 / 2〜6 日前 50% / 前日・当日 100%）を入れておく

## 要望と対応

| 要望（ヒアリング済み） | 対応 |
|---|---|
| 部屋は 1 部屋のみ | `room_count`（既定 1）。将来の複数部屋にも同じ設計で対応 |
| チェックイン 15:00 以降 / チェックアウト翌 10:00 | `check_in_time` / `check_out_time`。お客様は時刻を選ばない（選ばせたい場合は `check_in_time_options` を設定） |
| 11/1〜11/2 の予約があっても 11/2 15:00 から別のお客様を受けたい | **「泊（夜）」を単位にして空きを判定**（後述） |
| チェックイン日とチェックアウト日を選んで予約 | カレンダーを 2 回タップ |
| 時間の表示は不要。◯× は欲しい | 各日のマスに「料金」（= 空き）か「空室なし」 |
| 曜日・シーズン別の料金、日数分の自動計算 | 「料金表」を複数持ち、曜日 / 祝前日 / 祝日 / 季節 / 特定日に割り当て。1 泊ずつ決めて合計 |
| 人数で料金が変わる（1 名 14,000 / 2 名 20,000 / 3 名 26,000。0〜5 歳無料、6 歳以上は 1 人扱い） | 料金表は「有料人数 → 1 泊料金」。人数の区分（`guest_categories`）は店舗が自由に作り、各区分を「有料人数に数える / 無料 / 1 人 1 泊 ○円加算」から選ぶ |
| 連泊割引 | `long_stay_discounts`（N 泊以上で % / 1 泊あたり円 / 合計から円。段階可） |
| 12 か月先まで | `advance_booking_days` = 365 |
| 前日の午前中まで翌日の予約可 | 既存の条件付き受付開始を宿泊でも使う: `min_advance_days: 1` + `{ from_time: '12:00', min_days: 2 }`。時刻は設定で変更可 |
| 最大 7 泊 | `max_nights` = 7 |
| LINE と Web の両方 | 同じ宿泊モードで `form_type` line / web の 2 フォーム。「他フォームにも反映」で同期 |
| キャンセルポリシー（当日・前日 100% / 〜1 週間前 50% / それ以前 無料） | 段階式キャンセル料 `cancel_rules.fee_tiers`（日数 + 任意の時刻境界）。規定文の自動生成、LINE キャンセル時に金額を提示して確認（または施設へ誘導）、記録と通知。**請求（決済）はしない** |

## 空きの考え方（最重要）

単位は「夜（night）」。日付 `d` の夜 = `d` のチェックイン時刻 〜 `d+1` のチェックアウト時刻。

- 予約 `[checkin, checkout)` は `checkin` 〜 `checkout − 1` の夜を使う（チェックアウト日の夜は使わない）
- 夜 `d` が埋まっている = その夜を使う有効な予約（`status <> 'cancelled'`）の数 + その夜の時間帯に重なる Google カレンダーの予定（店舗カレンダー + `block_calendar_ids`）の数 が `room_count` 以上
- 夜 `d` が受けられない = 休業（`closed_weekdays` / `closed_dates` / `closed_ranges`）、祝日不可（`holidays_as_closed`）、受付期間外（`resolveEarliestBookable` の日数より前、`advance_booking_days` より先）
- カレンダーのマス `d` に出すのは「夜 `d` に泊まれるか」と「夜 `d` の料金」（選択中の人数で計算）
- チェックイン日に選べる = 夜 `d` が空いていて受けられる
- チェックアウト日に選べる = `checkin` 〜 `d − 1` の夜がすべて空いていて、泊数が `min_nights`〜`max_nights`。**夜 `d` 自体は埋まっていてもよい**（Airbnb と同じ）

例: A が 11/1 〜 11/2 で予約 → 11/1 の夜だけ埋まる。11/2 は料金表示（空き）。B は 11/2 にチェックインできる。C が 10/31 チェックインなら 11/1 をチェックアウト日に選べる。

受付期限の例（前日の午前中まで）: `min_advance_days: 1`、`conditional_advance_rules: [{ from_time: '12:00', min_days: 2 }]`。10/30 11:59 までは 10/31 チェックインを選べ、12:00 を過ぎると 11/1 以降だけになる。既存の `resolveEarliestBookable(cs, now)` をそのまま使う（`start_time` は宿泊では無視）。

### 1 泊の料金の決め方
1. 料金表の選択（上が強い）: `date_rate_table_ids` > `seasons` > `holiday_rate_table_id`（祝日の夜） > `holiday_eve_rate_table_id`（祝前日の夜） > `weekday_rate_table_ids[dow]` > `default_rate_table_id`
2. 有料人数 = `charge: 'adult'` の区分の人数の合計
3. 料金表の金額: `by_count` は `prices[有料人数]`（表の最大人数を超えたら `extra_person_price` × 超過人数を加算。無ければ受けられない = `null`。表に無い少人数も `null`）。`per_person` は `per_person_price` × 有料人数
4. `charge: 'fixed_per_night'` の区分は `price` × 人数 を加算
5. 合計 = Σ 各夜の料金 − 連泊割引（`min_nights` を満たす最大の段階を 1 つ。`percent` は合計に、`per_night` は泊数 × 値、`total` は値。0 円未満にしない）

祝日判定は既存の `HOLIDAY_RUNTIME_JS` と同じ計算（純粋ロジックには `isHoliday(date)` を渡す）。

### キャンセル料の決め方
- `daysBefore` = チェックイン日 − 操作日（JST の日付差。当日 0、前日 1、過ぎていればマイナス）
- `fee_tiers` を `days_before` の大きい順に見て、最初に当てはまる段階の `percent`。当てはまる = `daysBefore > days_before`、または `daysBefore === days_before` かつ（`until_time` 無し または 現在時刻 < `until_time`）
- 当てはまる段階が無ければ最後（`days_before` が最小）の段階の `percent`。`fee_tiers` が空なら 0%
- 例 A（日数のみ）: `[{7, 0%}, {2, 50%}, {0, 100%}]` = 7 日前以前 無料 / 2〜6 日前 50% / 前日・当日 100%
- 例 B（時刻付き）: `[{7, 0%}, {1, until 18:00, 50%}, {0, 100%}]` = 前日 18:00 まで 50%、以降 100%
- 金額 = `percent` × 基準額（`fee_base`）。10 円未満切り捨て
- 既存の `deadline_hours` は従来どおり「LINE から一切キャンセルできなくなる期限」として先に判定する
- `self_cancel_with_fee = 'confirm'`: 「キャンセル料 50%（10,000 円）が発生します。キャンセルする場合は『キャンセル確定: N』と送信してください」→ 「キャンセル確定: N」で再計算のうえ取り消し。`'deny'`: 金額を案内し、施設へ連絡するよう返す（取り消さない）
- 規定文: `policy_text` が空なら `buildCancelPolicyText(rules)` が段階表から自動生成（「7 日前まで: 無料 / 2〜6 日前: 50% / 前日・当日: 100%」）

宿泊モードのとき **使わない** 既存設定: `business_hours` / `holiday_hours` / `special_business_days` / `blocked_times` / `time_interval` / `extra_minutes` / `multiple_dates_settings` / `allow_exceed_business_hours` / `max_concurrent_events`（代わりに `room_count`）/ `min_advance_hours` / スタッフの希望日時設定。**使う** 既存設定: `advance_booking_days` / `min_advance_days` / `conditional_advance_rules`（日数部分のみ）/ `holidays_as_closed` + `excluded_holiday_types` / `show_customer_*` / `require_customer_*` / `show_message_field` / `show_customer_email` / `notification_email` / `max_concurrent_reservations_per_user` / `cancel_rules`。

`normalizeForm()`: `stay_settings` があれば常に `sanitizeStaySettings()` で補完（料金表 0 件なら「基本」を作る。参照先の無い料金表 ID は基本に戻す。人数区分 0 件なら「6歳以上」(adult, 1〜4) と「0〜5歳」(free, 0〜3) を作る。モードを戻しても設定が消えない）。`cancel_rules` は `resolveCancelRules` が `fee_tiers` / `fee_base` / `self_cancel_with_fee` も補完する。

## DB（第 2 段階。`20261101000000_add_stay_reservation.sql`）

```sql
ALTER TABLE reservations
  ADD COLUMN IF NOT EXISTS checkout_date DATE,          -- NULL = 宿泊以外の予約
  ADD COLUMN IF NOT EXISTS stay_nights INTEGER,
  ADD COLUMN IF NOT EXISTS guest_counts JSONB,          -- { "<category_id>": 人数 }
  ADD COLUMN IF NOT EXISTS guest_count INTEGER,         -- 有料人数（一覧・分析用）
  ADD COLUMN IF NOT EXISTS stay_price_total INTEGER,    -- 割引後の宿泊料金（円。サーバー再計算値）
  ADD COLUMN IF NOT EXISTS cancel_fee_percent INTEGER,
  ADD COLUMN IF NOT EXISTS cancel_fee_amount INTEGER,
  ADD COLUMN IF NOT EXISTS cancelled_at TIMESTAMPTZ;

ALTER TABLE reservations
  ADD CONSTRAINT reservations_checkout_after_checkin
  CHECK (checkout_date IS NULL OR checkout_date > reservation_date);

CREATE INDEX IF NOT EXISTS idx_reservations_stay_range
  ON reservations (store_id, reservation_date, checkout_date)
  WHERE checkout_date IS NOT NULL;
```

- `reservation_date` = チェックイン日、`reservation_time` = チェックイン時刻（既定 `check_in_time`。`check_in_time_options` からお客様が選んだ場合はその値）。**リマインダー 3 種・フォロー・来店履歴は変更なしで動く**
- `customer_info` にも内訳: `stay_per_night` / `stay_subtotal` / `stay_discount` / `guest_counts` / `guest_labels`
- 二重予約防止: DB 関数 `stay_insert_reservation_checked(p_row JSONB, p_room_count INT)`（`lottery_insert_entry_checked` と同じ考え方）。`pg_advisory_xact_lock(hashtext(store_id))` → 各夜の有効予約数 ≥ `room_count` なら `RAISE EXCEPTION 'stay_full'` → INSERT。Google カレンダー側の重なりはアプリ側で直前に再確認
- Local 環境（`data/reservations.json`）はアプリ内で同じ判定

## API（第 2 段階）

### 新規 `GET /api/stores/{storeId}/stay/availability?form_id=&from=&to=&guests=`
- 公開。夜ごとの `{ available, remaining, price }` のみ返す。`guests` = `{ "<category_id>": n }` を JSON（省略時は各区分の `min`）。`to − from` は最大 93 日
- フォーム設定 → `reservations`（`status <> 'cancelled'`・`checkout_date > from`・`reservation_date < to`）→ 店舗カレンダー + `block_calendar_ids` を `listCalendarEvents` → `buildNightStatus()`
- **料金もここで計算して返す**（静的 HTML に焼き込むと料金変更のたびに再デプロイ + 公開プロキシの 1 時間キャッシュ）。人数変更時はフォームが再取得
- カレンダー取得失敗時は DB だけで判定し `calendar_degraded: true`。既存の `/calendar/availability` は変更しない

### `POST /api/reservations`（拡張）
- 追加: `booking_mode: 'stay'` / `checkout_date` / `guest_counts` / `stay_nights` / `stay_price_total`（後 2 つは参考値）/ `reservation_time`（`check_in_time_options` から選んだとき）
- 検証: `checkout_date > reservation_date`、泊数の範囲、受けられない夜を含まない（休業・祝日不可・受付期間）、`validateGuestCounts`、料金が計算できる。`reservation_time` は `check_in_time_options` に含まれる値以外は `check_in_time` に置き換え
- **料金はサーバーで再計算**（`computeStayTotal`）して保存。空き再チェック（カレンダー → DB 関数）。埋まっていれば `409 { code: 'slot_taken' }`
- カレンダー予定: `start = reservation_date T reservation_time`、`end = checkout_date T check_out_time`。タイトルに「◯泊・◯名」。来店履歴の `amount` に `stay_price_total`

### `PATCH /api/reservations/{id}` ／ LINE Webhook（拡張）
- PATCH: `checkout_date` / `guest_counts` の編集 → 料金再計算 + `updateReservationEvent`。`cancelled` で `cancel_fee_*` と `cancelled_at` を保存（body で上書き可）。復元でクリア
- Webhook: 「キャンセル: N」→ `deadline_hours`（既存）→ `resolveCancelFee` → `self_cancel_with_fee` に従って確認 / 誘導。「キャンセル確定: N」を新規コマンドに。`parseReservationForm()` に `《チェックイン》`（→ `date1`）/ `《チェックアウト》`。予約確認 / キャンセル一覧は「11/1(日) 〜 11/4(月) 3泊」

## 静的 HTML（第 3 段階。`StaticReservationGenerator`、宿泊モードのとき）

- `renderDateTimeFields()` で `booking_mode === 'stay'` のとき `renderStayField()`。時間スロット・スタッフカレンダー判定は出さない
- **人数**: 日付の前に `guest_categories` の数だけプルダウン（`min`〜`max`）。変更で料金を取り直してカレンダーの金額を更新
