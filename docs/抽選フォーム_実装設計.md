# 抽選フォーム 実装設計書（推奨案）

作成日: 2026-09-03 / 対象: テナント管理画面の店舗ページ・店舗管理者ページ・静的フォーム（LINE LIFF）

---

## 1. この資料について

店舗ごとに **「抽選フォーム」** を作成・公開し、お客様が LINE から抽選に参加すると、
**抽選結果が公式 LINE のトークルームに届き**、店舗側は **抽選履歴（誰が・いつ・何に当たったか・引換済みか）** を管理画面で確認できる機能の設計書です。

既存の「予約フォーム」「アンケートフォーム」と同じ仕組み（`config` JSONB → 静的 HTML 生成 → Supabase Storage 配信）に乗せる前提で、
**どのような抽選フォームにするかの推奨案** と **画面デザイン案** をまとめています。
「10. 決定事項」は 2026-09-03 に回答済みです。本文はその決定を反映した **確定版** です。

### やりたいこと（要望の整理）

1. テナント側 店舗ページのタブを **概要 / 予約フォーム / アンケート / 抽選フォーム / 設定** の並びにする
2. 抽選フォームは **いろいろカスタマイズできる**（賞品・確率・在庫・参加制限・期間・演出・文言・色）
3. 抽選結果が **公式 LINE のトークルームに送信される**
4. **抽選履歴** を店舗管理者ページから確認できる（＋当選の引換管理）

## 2. 推奨する抽選フォームの姿（結論）

| 項目 | 推奨 | 理由 |
|---|---|---|
| 抽選方式 | **即時抽選（その場で結果が出る）** と **後日抽選（応募を集めて締切後に当選者を決める）** の 2 方式。フォーム作成時に選ぶ | 即時型は来店促進・友だち追加のフック、後日型はプレゼントキャンペーン向け。両方 v1 で実装（決定） |
| 対象チャネル | **LINE（LIFF）専用**。Web 版は作らない | 「1 人 1 回」などの公平性を担保するには LINE ユーザー ID が必須。Web だと匿名で何度でも引けてしまう |
| 結果の決定 | **サーバー側で抽選**（`crypto.randomInt`）してから、クライアントで演出を再生 | クライアント抽選は改ざんできる。演出は「見せ方」に徹する |
| 結果の通知 | **① LIFF `sendMessages` でお客様側から結果テキストを送信（必須）** + **② 店舗にチャネルアクセストークンがあれば Bot から Flex メッセージ（当選カード）を push（任意）** | ① は予約・アンケートと同じ仕組みで無料・確実。② はリッチな当選カード＋引換コードを届けられる（push 通数を消費） |
| 賞品設定 | 賞品ごとに **当選確率（%）・在庫数・画像・引換条件** を設定。「はずれ」は残り確率で自動計算 | 「A 賞 1%、B 賞 10%、残りはずれ」という運用が直感的 |
| 参加制限 | **1 人 1 回 / 1 日 1 回 / 期間中 N 回** から選択。友だち追加必須オプションあり | キャンペーンごとに運用が違う |
| 演出 | **スクラッチ / ガチャ / シンプル** の 3 種から選択（既定: スクラッチ） | 指で削るスクラッチは LINE キャンペーンで一番「らしい」。ガチャは CSS アニメ、シンプルは演出なしで軽量 |
| 引換 | 当選結果に **6 桁の引換コード** を発行。フォームごとに **「コード方式」か「QR 方式」を管理画面で選択**。コード方式は履歴からコード検索して「引換済み」、QR 方式は店舗スタッフ用スキャン画面で読み取って「引換済み」 | 小規模店はコード、混雑店やイベントは QR が速い（決定） |
| 事前質問 | 抽選前に **任意の質問**（お名前・電話番号・自由入力など）を追加可能。**問数制限なし**（アンケートの質問エディタをそのまま再利用） | 抽選とアンケートを 1 フォームで兼ねられる（決定） |
| 本人確認 | LIFF の ID トークンを **サーバーで検証**。チャネル ID は `stores.line_channel_id` を優先し、未設定なら環境変数 `NEXT_PUBLIC_LINE_CHANNEL_ID` | 店舗が独自の LINE 公式アカウント（別チャネル）を使うケースに対応（決定） |

## 3. お客様側の体験フロー（LINE）

### 3-1. 即時抽選

```
公式 LINE トーク or リッチメニュー
  └─ 抽選フォーム URL をタップ（LIFF）
       │
       ├─ ① LIFF 初期化 → LINE ログイン → 友だち状態取得（既存アンケートと同じ）
       │     ・LINE 以外のブラウザ: 「LINE アプリから開いてください」案内（予約フォームの line_only と同じ画面）
       │     ・友だち追加必須 ON で未追加: 「友だち追加してから抽選してください」＋友だち追加ボタン
       │
       ├─ ② トップ画面
       │     ・タイトル / 期間 / 賞品一覧（画像・賞品名。確率表示は ON/OFF）
       │     ・注意事項（お一人様 1 回、当選は店頭で引換 など）
       │     ・（設定時）事前質問（問数制限なし）
       │     ・大きな「抽選する」ボタン
       │
       ├─ ③ 参加可否チェック（サーバー）
       │     ・期間外 → 「受付期間外です」
       │     ・回数上限 → 「本日はすでに参加済みです」＋前回結果を再表示
       │     ・在庫切れなどで全賞品が引けない → はずれ扱い or 「終了しました」（設定で選択）
       │
       ├─ ④ 演出（スクラッチ: 指で削る / ガチャ: レバーを引く / シンプル: ドラムロールのみ）
       │     ・結果はすでにサーバーで確定済み。演出はその結果を「開示」するだけ
       │
       ├─ ⑤ 結果画面
       │     ・当選: 紙吹雪 + 賞品カード（画像・賞品名・引換コード・有効期限・引換方法）
       │     ・はずれ: やわらかい文言 + 「次回のご来店をお待ちしております」＋（設定時）残念賞クーポン
       │     ・「LINE に結果を送る」ボタン（= 送信ボタン）
       │
       └─ ⑥ LIFF sendMessages でトークに結果テキストを送信 → ウィンドウを閉じる
             ・（店舗にアクセストークンあり & push ON）Bot から Flex 当選カードを push
             ・2 通目固定テキスト（既存の second_message と同じ）→ 公式 LINE の完全一致応答でクーポン配布も可能
```

**ポイント:** 結果は「送信ボタンを押す前」にサーバーに保存済みです。お客様が途中で閉じても履歴は残り、再度開いたときは同じ結果を再表示します（二重抽選を防ぐ）。

### 3-2. 後日抽選

```
お客様（応募期間中）
  ├─ ① 〜 ② は即時抽選と同じ（LIFF ログイン・トップ画面・事前質問）
  ├─ ③ 「応募する」→ サーバーが応募を記録（status = entered）。回数制限は「1 人 1 口」固定
  ├─ ④ 応募完了画面（「抽選結果は ○月○日以降に LINE でお知らせします」）
  └─ ⑤ LIFF sendMessages で応募完了テキストを送信 → ウィンドウを閉じる
        （2 通目固定テキストも即時抽選と同様に利用可）

店舗（締切後）
  ├─ ⑥ 管理画面の「抽選を実行」ボタン → 賞品ごとの当選数（= 在庫数）だけ応募者からランダムに選ぶ（crypto.randomInt）
  │     ・結果は「仮当選」として一覧表示。管理者が当選者の入れ替え・取り消しができる
  ├─ ⑦ 「当選を確定して通知」ボタン → 当選者に Bot から Flex 当選カードを push（引換コード / QR 付き）
  │     ・落選者には push しない（通数節約）
  │     ・チャネルアクセストークン未設定の店舗は「後日抽選」フォームを作成できない（作成時にエラー表示）
  └─ ⑧ 通知後、お客様がフォームを開き直すと結果画面（当選 / 落選）が表示される
```

**ポイント:** 後日抽選は LIFF の `sendMessages`（お客様側からの送信）が使えないため、結果通知は Bot push が必須です。
自動抽選の結果は確定前に手動で修正できます（例: 従業員の当選を外す）。

## 4. 画面デザイン案

### 4-1. デザイン方針

- 既存の予約・アンケートフォームと同じ **「テーマカラー × 補色アクセント」**（`theme_color` → `computeAccentColor()`）を踏襲し、店舗のブランドに馴染ませる
- ただし抽選は「ワクワク感」が命なので、**ヒーロー領域（演出ステージ）だけは彩度を上げる**。グラデーション背景・浮遊する装飾ドット・大きなボタン
- 幅 500px 上限の 1 カラム、`100dvh` 基準、ボタン高さ 56px 以上、`prefers-reduced-motion` 時は演出を省略
- フォント: 既存と同じ `Noto Sans JP`。結果画面の賞品名のみ大きく（28px, 700）

### 4-2. トップ画面（ワイヤーフレーム）

```
┌──────────────────────────────┐
│ ▓▓▓▓ ヘッダー（theme_color） ▓▓▓▓ │  ← 上端 4px にアクセント色ライン
│   [ロゴ]  夏の来店感謝くじ        │
│   9/1（月）〜 9/30（火）           │  ← 期間バッジ（白抜き）
├──────────────────────────────┤
│                              │
│   ┌────────────────────┐     │
│   │  ✦ 演出ステージ ✦    │     │  ← グラデ背景 + 装飾。スクラッチなら
│   │   [銀色のスクラッチ]  │     │     銀色の板、ガチャならカプセル筐体
│   │    「ここを削ってね」  │     │
│   └────────────────────┘     │
│                              │
│  ▎賞品                        │  ← 既存の field-label（左アクセント線）
│  ┌──────┐ ┌──────┐ ┌──────┐   │
│  │ [画像] │ │ [画像] │ │ [画像] │   │  ← 横スクロールカード
│  │ A賞    │ │ B賞    │ │ C賞    │   │
│  │ 30%OFF │ │ ドリンク│ │ ステッカー│   │
│  │ 残り3  │ │  1%   │ │  10%  │   │  ← 在庫/確率表示は設定で ON/OFF
│  └──────┘ └──────┘ └──────┘   │
│                              │
│  ▎ご注意                      │
│  ・お一人様 1 回まで            │
│  ・当選は店頭でこの画面をご提示  │
│                              │
│  ▎お名前（任意の事前質問）      │
│  [                    ]      │
│                              │
├──────────────────────────────┤
│ ┃  🎯 抽選する               ┃ │  ← 固定フッター、アクセント色、56px
└──────────────────────────────┘
```

### 4-3. 演出の 3 パターン

| パターン | 操作 | 実装 | 向いている店舗 |
|---|---|---|---|
| **スクラッチ（既定）** | 指で銀色の板をこすると下から結果が見える。70% 削れたら自動で全開＋結果画面へ | `<canvas>` の `globalCompositeOperation = 'destination-out'`。約 120 行の vanilla JS | 飲食・美容・小売全般 |
| **ガチャ** | 「レバーを回す」ボタン → 筐体が揺れてカプセルが落ちる → カプセルをタップで開く | CSS keyframes のみ（`@keyframes shake / drop / pop`）。画像は SVG インライン | 物販・イベント |
| **シンプル** | ボタンを押すと 1.5 秒のドラムロール（賞品名が高速で切り替わる）→ 停止 | `setInterval` で賞品名を差し替え、easing で減速 | 演出を控えたい店舗・高齢層 |

すべて **結果はサーバーから受け取った `prize_id` を表示するだけ**。演出中に通信は発生しません。

```

┌──────────────────────────────┐    ┌──────────────────────────────┐
│ ✨ 🎉 ✨  紙吹雪（2 秒）       │    │                              │
│                              │    │      🍀                       │
│      おめでとうございます！      │    │   残念、今回ははずれでした      │
│                              │    │                              │
│  ┌────────────────────────┐  │    │  次回のご来店もお待ちして       │
│  │ [賞品画像]               │  │    │  おります！                   │
│  │  A 賞                   │  │    │                              │
│  │  お会計 30% OFF          │  │    │  ┌────────────────────────┐  │
│  │  ─────────────────      │  │    │  │ 残念賞: ドリンク 1 杯無料 │  │ ← 設定時のみ
│  │  引換コード              │  │    │  │ 引換コード  7X4K2P       │  │
│  │  ██ 7X4K2P ██           │  │    │  └────────────────────────┘  │
│  │  有効期限 2026/10/31     │  │    │                              │
│  │  店頭でこの画面をご提示     │  │    │                              │
│  └────────────────────────┘  │    │                              │
│                              │    │                              │

└──────────────────────────────┘    └──────────────────────────────┘
```

- 賞品カードの左端は **賞品ごとの「ランク色」**（金 / 銀 / 銅 / 任意 HEX）を帯で表示
- 引換コードは等幅・字間広め・コピー用タップ対応
- **QR 方式のフォームでは、QR コード（180px、`/api/lotteries/qr/{token}.png`）を表示**。QR の中身は `https://{app}/r/{32 文字トークン}`（店舗スタッフ用スキャン画面が読み取る）。QR の下に 6 桁コードも併記し、スキャンできないときの手入力に使う
- 後日抽選の応募完了画面は結果画面と同じレイアウトで、カードの中身を「応募を受け付けました / 抽選日 ○月○日 / 結果は LINE でお知らせします」に差し替える
- はずれ文言は編集可能（既定「残念、今回ははずれでした」）。「はずれ」という強い言葉を避けたい店舗向けに「またチャレンジしてね」等に差し替え可能

### 4-5. LINE トークに届くメッセージ

**① お客様側から送信されるテキスト（LIFF `sendMessages`、必須）**

```
🎯 夏の来店感謝くじ に参加しました
結果：A 賞「お会計 30% OFF」
引換コード：7X4K2P
有効期限：2026/10/31

※店頭でこの画面をご提示ください
```
文面はテンプレート編集可（プレースホルダ: `{賞品名}` `{引換コード}` `{有効期限}` `{店舗名}` `{LINE名}`）。
2 通目固定テキスト（既存 `second_message` と同じ）を続けて送れるので、公式 LINE の「完全一致応答」でクーポン画像を自動返信する運用も可能。

**② Bot からの Flex メッセージ（任意、`stores.line_channel_access_token` がある店舗のみ）**

```
┌──────────────────────────┐
│ ▓▓ 【当選のお知らせ】 ▓▓   │  ← ヘッダー: ランク色
│ [賞品画像 16:9]            │
│ A 賞                      │
│ お会計 30% OFF             │
│ ──────────────────────── │
│ 引換コード   7X4K2P        │
│ 有効期限     2026/10/31    │
│ ──────────────────────── │
│ 店頭でこの画面をご提示ください │
│ [ 店舗の地図を見る ]        │  ← 任意ボタン（URL）
└──────────────────────────┘
```
はずれ時は push しない（通数節約）。既存リマインダーの Flex ビルダー（`reminder-template.ts` の色指定パターン）を流用。

## 5. 管理画面の設計

### 5-1. テナント側 店舗ページ（`/tenant/{slug}/admin/{storeId}`）

タブを **概要 / 予約フォーム / アンケート / 抽選フォーム / 設定** の 5 つに変更（`page.tsx` の `TabsTrigger` に `lotteries` を追加）。

**抽選フォーム一覧カード**（アンケートカードと同じ骨格）

```
┌─────────────────────────────────────────────────┐
│ 🎯 夏の来店感謝くじ          [公開中] [受付中 9/1–9/30] │
│ 参加 128 / 当選 41（32%）/ 引換 17                  │
│ A 賞 残り 3 ・ B 賞 残り 0 ・ C 賞 ∞                │
│ [編集] [プレビュー] [URL コピー] [履歴] [複製] [削除]  │
└─────────────────────────────────────────────────┘
```

**抽選フォーム編集モーダル**（`FormEditModal` に `lottery` 種別を追加。タブ構成:）

| タブ | 設定項目 |
|---|---|
| 基本情報 | **抽選方式（即時 / 後日）** / タイトル / 店舗名 / LIFF ID / テーマカラー / ロゴ / 受付期間（開始・終了） / **後日抽選の抽選予定日** / 注意事項 / **引換方式（6 桁コード / QR コード）** / 公開状態 |
| 賞品と確率 | 賞品行の追加・並び替え（D&D）。各行: 賞品名 / 説明 / 画像 / ランク色 / **当選確率 %（即時のみ）** / **在庫数 = 当選数（空 = 無制限、後日抽選では必須）** / 有効期限（日数 or 日付） / 引換方法テキスト。合計が 100% を超えたら保存不可。残りは自動で「はずれ」。「残念賞（はずれ時に必ず付与）」の ON/OFF |
| 参加条件 | 参加回数（1 人 1 回 / 1 日 1 回 / 期間中 N 回。後日抽選は 1 人 1 口固定）/ 友だち追加必須 / 全賞品在庫切れ時の挙動（はずれ扱い or 受付終了）/ 事前質問（問数制限なし。`SurveyQuestionEditor` をそのまま再利用し、追加質問・その他・D&D も使える） |
| 演出・デザイン | 演出（スクラッチ / ガチャ / シンプル）/ スクラッチの板デザイン（銀 / 金 / 画像）/ 確率の表示 ON/OFF / 在庫の表示 ON/OFF / 紙吹雪 ON/OFF / 当選・はずれの見出し文言 |
| メッセージ | 結果テキストのテンプレート（当選用・はずれ用）/ 2 通目固定テキスト / Bot Flex push の ON/OFF |

「保存」「保存＆デプロイ」「プレビュー」は既存と同じ。プレビューは `POST /api/preview/generate` に `formType: 'lottery'` を追加し、プレビューでは抽選 API を呼ばず **ダミー結果でランダムに演出だけ確認**できるようにする。

### 5-2. 店舗管理者ページ（`/{storeId}/admin`）

`STORE_ADMIN_TABS` に **`lotteries`（抽選管理）** を追加（アンケート管理と設定の間）。`admin_visible_tabs` の ON/OFF 対象にも含める。

**抽選管理タブの構成**

1. **サマリーカード**: 参加数 / 当選数 / 当選率 / 引換率（フォーム・期間で絞り込み）
2. **抽選フォーム一覧**: 公開状態、期間、URL コピー、プレビュー（編集はテナント側と同じモーダル。店舗管理者にも編集を許すかは要確認）
3. **抽選履歴テーブル**（要望の中心）

```
┌────────────┬──────────┬───────────────┬──────┬────────┬────────┬────────────┐
│ 日時        │ LINE 名   │ 賞品           │ コード │ 状態    │ 引換    │ 備考        │
├────────────┼──────────┼───────────────┼──────┼────────┼────────┼────────────┤

```

- 行タップで詳細（事前質問の回答、顧客ページへのリンク、引換取り消し）
- 店頭運用（コード方式）: お客様がコードを見せる → 検索欄にコード入力 → 「引換済にする」。**引換コードは店舗内でユニーク**にして検索 1 発で特定できるようにする
- 店頭運用（QR 方式）: 履歴画面右上の **「QR をスキャン」ボタン** → カメラ画面（`/{storeId}/admin/lottery-scan`、`BarcodeDetector` API、非対応端末は jsQR にフォールバック）→ 読み取ると当選内容を表示し「引換済にする」ボタン。期限切れ・引換済み・他店舗の QR は赤で警告。手入力欄も併設
- 顧客管理（CRM）と連携: `line_user_id` で `customers` に自動紐付け（既存 `customer-utils.ts` の仕組み）。顧客詳細に「抽選履歴」セクションを追加（v1 では一覧のみ）

4. **後日抽選の管理パネル**（後日抽選フォームを選択したときのみ表示）

```
┌─────────────────────────────────────────────────┐
│ 秋のプレゼントキャンペーン   応募 312 件 / 締切 9/30 23:59 │
│ 状態: 応募受付中 → 締切済み → 仮当選 → 確定・通知済み       │
│                                                 │
│ [抽選を実行]  ← 締切後に有効。賞品ごとの当選数だけランダム抽出 │
│                                                 │
│ 仮当選者（A 賞 3 名 / B 賞 10 名）                  │
│  A 賞  田中 太郎   [外す]     B 賞  さくら   [外す]    │
│  A 賞  Yuki       [外す]     ...                  │
│  [応募者から追加 ▼]                                │
│                                                 │
│ [当選を確定して LINE で通知]  ← 確認ダイアログ → 当選者に Flex push │
└─────────────────────────────────────────────────┘
```

- 「外す」で仮当選を取り消すと、その枠は「応募者から追加」で手動補充する（自動再抽選はしない。意図しない当選者が増えるのを防ぐ）
- 確定後は当選者の変更不可（引換取り消しのみ可）。通知失敗（ブロック等）は `push_sent = false` として一覧に「未通知」バッジ表示、再送ボタンあり

**ダッシュボードタブ**: 既存の統計カード（予約 / 顧客 / アンケート）に「本日の抽選参加数」を追加。

CREATE FUNCTION lottery_insert_entry_checked(p_form_id, p_line_user_id, p_prize_id, p_prize_stock, p_window_start, p_max_entries, p_entry JSONB)
  RETURNS JSONB -- FOR UPDATE で lottery_forms 行をロック → 回数チェック → 在庫チェック → INSERT。{ok, reason: limit | sold_out | not_found}
-- service_role のみ実行可。TS 側は sold_out のとき「はずれ（残念賞）」として記録し直す

| `POST /api/stores/{storeId}/lotteries` | 作成（テンプレート: 空 / 3 賞品サンプル） | 管理者 |

| `PUT /api/lotteries/{id}` | 更新（**オブジェクト全体を渡す**。`draft_config` と `config` の両方を扱う） | 管理者 |
| `DELETE /api/lotteries/{id}` | 削除（履歴もカスケード） | 管理者 |
| `POST /api/lotteries/{id}/deploy` | 静的 HTML 生成 → Storage アップロード | 管理者 |
| `POST /api/lotteries/{id}/duplicate` | 複製（履歴はコピーしない） | 管理者 |
| `POST /api/lotteries/draw` | **抽選実行**。body: `lottery_form_id, store_id, id_token, line_display_name, line_friend_flag, answers, user_agent` | 公開（ID トークン検証） |
| `GET /api/lotteries/{id}/my-result?id_token=` | 同一ユーザーの直近結果（再訪時の再表示用） | 公開（ID トークン検証） |
| `PATCH /api/lotteries/{id}/my-result` | `{ id_token, message_sent: true }` で LIFF 送信完了を記録 | 公開（ID トークン検証） |
| `GET /api/stores/{storeId}/lotteries/entries` | 抽選履歴一覧（`form_id / prize_id / status / search / from / to / limit / offset`） | 管理者 |
| `PATCH /api/stores/{storeId}/lotteries/entries/{entryId}` | `{ action: 'redeem' \| 'unredeem' \| 'cancel' \| 'restore', note? }`。期限切れ・二重引換は拒否 | 管理者 |
| `GET /api/stores/{storeId}/lotteries/entries/export` | CSV 出力 | 管理者 |
| `GET /api/stores/{storeId}/lotteries/redeem/{qrToken}` | QR スキャン / コード手入力時の当選内容照会（32 文字の QR トークンまたは 6 桁コード。店舗境界・期限・引換済みを判定し `can_redeem` / `reason` を返す） | 管理者 |
| `POST /api/lotteries/{id}/deferred/draw` | 後日抽選の自動抽選（締切後のみ。`provisional` を作成。再実行で前回の仮当選を破棄して引き直し） | 管理者 |
| `PATCH /api/lotteries/{id}/deferred/winners` | 仮当選の入替（`remove: entryId[]`, `add: [{entryId, prizeId}]`） | 管理者 |
| `POST /api/lotteries/{id}/deferred/confirm` | 当選確定 → `drawn` / `lost` に更新 → 当選者へ Flex push → `deferred_notified_at` | 管理者 |
| `POST /api/lotteries/{id}/deferred/resend` | 未通知の当選者に再送 | 管理者 |
| `POST /api/preview/generate` | `formType: 'lottery'` を追加 | 管理者 |

**`POST /api/lotteries/draw` は `lottery_type` で分岐**: 即時なら抽選、後日なら「応募」（`status = entered`、1 人 1 口）として記録し、応募完了テキストを返す。

**ID トークン検証（`src/lib/line-verify.ts`）**: `stores.line_channel_id` → 未設定なら `NEXT_PUBLIC_LINE_CHANNEL_ID` の順でチャネル ID を決め、`POST https://api.line.me/oauth2/v2.1/verify` に `id_token` と `client_id` を送る。`sub` が LINE ユーザー ID。期限切れ・チャネル不一致は 401 `LINE の認証に失敗しました。もう一度開き直してください`。

**`POST /api/lotteries/draw` の処理順**

1. `id_token` を LINE の `https://api.line.me/oauth2/v2.1/verify` で検証し `line_user_id` を確定（アンケートはクライアント申告の `line_user_id` を信用しているが、抽選は金銭価値があるためサーバー検証を必須にする）
2. フォームが `active` かつ期間内か確認
3. `draw_lottery()` RPC を呼ぶ（回数制限・在庫・当選判定・INSERT を 1 トランザクションで）
4. 当選時は引換コードを生成（衝突時は再生成）、有効期限を計算
5. `customers` に自動紐付け（`findOrCreateCustomer` 相当）
6. `push_flex_enabled` かつ店舗トークンあり → Flex push（失敗しても抽選結果は返す。`push_sent=false` で記録）
7. 結果（`prize`, `redeem_code`, `expires_at`, `message_text`）を返す → クライアントが演出後に `liff.sendMessages`

エラー時の日本語メッセージ例: `受付期間外です` / `本日はすでに参加済みです` / `この抽選は終了しました` / `LINE の認証に失敗しました。もう一度開き直してください`。
