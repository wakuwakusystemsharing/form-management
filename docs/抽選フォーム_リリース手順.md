# 抽選フォーム リリース手順（初心者向け）

作成日: 2026-09-03 / 対象ブランチ: `feature/lottery-form`

抽選フォーム機能（Phase 1〜5）を staging で動かし、本番に出すまでの手順です。
上から順番に進めれば完了します。**「確認」の項目で OK にならない場合は次に進まず、「困ったとき」を見てください。**

---

## 全体の流れ

| ステップ | やること | 所要時間の目安 |
|---|---|---|
| 1 | 変更をコミットして GitHub に push | 5 分 |
| 2 | Pull Request を作って staging にマージ | 10 分（自動チェック待ち含む） |
| 3 | Supabase（staging）にマイグレーションを 2 本流す | 10 分 |
| 4 | LINE Developers で必要な ID を集める | 15 分 |
| 5 | 管理画面で店舗設定と抽選フォームを作る | 15 分 |
| 6 | 実機の LINE で動作確認 | 20 分 |
| 7 | 本番へ | 20 分 |

## ステップ 1: 変更をコミットして push する

今は `feature/lottery-form` ブランチに、コミットされていない変更が 48 ファイルあります。

### 1-1. 今いるブランチと変更を確認

```bash
git branch --show-current
```

**確認:** `feature/lottery-form` と表示される。

```bash
git status --short
```

**確認:** `M`（変更）や `??`（新規）の行がたくさん出る。`data/` 配下のファイルが含まれて**いない**こと（`data/lottery_forms.json` などが出ていたら、それは動作確認で作られたものなので `git checkout -- data/` で戻す）。

### 1-2. コミット前チェック（必須）

```bash
pnpm type-check
node_modules/.bin/vitest run
```

**確認:** どちらもエラーなしで終わる（テストは `128 passed`）。

> `pnpm test` は pnpm 11 の「ビルドスクリプト承認」で止まることがあります。そのときは上のように `node_modules/.bin/vitest run` を直接実行してください（Windows PowerShell では `& node_modules/.bin/vitest.cmd run`）。

### 1-3. コミットして push

```bash
git add .
git commit -m "feat: 抽選フォーム機能（即時抽選・後日抽選・引換管理・LINE 通知）を追加"
git push -u origin feature/lottery-form
```

**確認:** 最後の行に `branch 'feature/lottery-form' set up to track 'origin/feature/lottery-form'` のような表示が出る。

## ステップ 2: Pull Request を作って staging にマージする

1. ブラウザで https://github.com/wakuwakusystemsharing/form-management を開く
2. 黄色い「Compare & pull request」ボタンを押す（出ていなければ「Pull requests」→「New pull request」）
3. **base を `staging`、compare を `feature/lottery-form`** にする
4. タイトル: `feat: 抽選フォーム機能`。本文には `docs/抽選フォーム_実装設計.md` を見るように一言書く
5. 「Create pull request」を押す
6. 自動チェック（ESLint / type-check / build）が緑になるのを待つ（数分）
7. 「Merge pull request」→「Confirm merge」

**確認:** Vercel が staging を自動デプロイし、数分後に https://form-management-staging.vercel.app が更新される。

> ⚠️ この時点ではまだ DB にテーブルがないため、staging の管理画面で抽選タブを開くと「抽選フォームの取得に失敗しました」と出ます。次のステップで直ります。

## ステップ 3: Supabase（staging）にマイグレーションを流す

新しいテーブルと DB 関数を作ります。ファイルは 2 本で、**必ずこの順番**で実行します。

| 順番 | ファイル | 内容 |
|---|---|---|
| 1 | `supabase/migrations/20260903000000_add_lottery.sql` | 抽選フォーム・抽選履歴テーブル、RLS、抽選用の DB 関数、監査ログの種別追加 |
| 2 | `supabase/migrations/20260903000001_add_store_line_channel_id.sql` | 店舗テーブルに LINE ログインチャネル ID 列を追加 |

### 3-1. Supabase Dashboard で実行する（おすすめ）

1. https://supabase.com/dashboard にログイン → **staging のプロジェクト**を選ぶ（本番と間違えないよう、プロジェクト名を必ず確認）
2. 左メニューの **SQL Editor** を開く
3. VS Code などで `supabase/migrations/20260903000000_add_lottery.sql` を開き、**全文コピー**して SQL Editor に貼り付け → 右下の **Run**
4. 画面下に `Success. No rows returned` と出れば OK
5. 同じ手順で `20260903000001_add_store_line_channel_id.sql` を実行

### 3-2. うまくいったか確認する

SQL Editor で次を実行します。

```sql
select table_name from information_schema.tables
 where table_name in ('lottery_forms', 'lottery_entries');
select column_name from information_schema.columns
 where table_name = 'stores' and column_name = 'line_channel_id';
select proname from pg_proc where proname = 'lottery_insert_entry_checked';
```

**確認:** 1 つ目で 2 行、2 つ目で 1 行、3 つ目で 1 行が返る。

> 2 回実行してしまっても壊れません（`IF NOT EXISTS` / `CREATE OR REPLACE` で書いてあります）。
> CLI に慣れている場合は `supabase link --project-ref <staging の ref>` → `supabase db push` でも同じことができます。

## ステップ 4: LINE Developers で必要な ID を集める

抽選フォームは LINE 専用なので、3 つの値が必要です。すべて https://developers.line.biz/console/ で取れます。

| 必要な値 | どこにあるか | 何に使うか |
|---|---|---|
| **LIFF ID**（例: `1234567890-abcdefgh`） | プロバイダー → **LINE ログイン**チャネル → 「LIFF」タブ → 追加した LIFF の ID | 抽選フォームの設定（フォームごと） |
| **チャネル ID**（10 桁の数字） | 同じ **LINE ログイン**チャネル → 「チャネル基本設定」タブ → チャネル ID | 店舗設定「LINE ログインチャネル ID」。お客様の本人確認に使う |
| **チャネルアクセストークン**（長い文字列） | プロバイダー → **Messaging API** チャネル → 「Messaging API 設定」タブ → 一番下の「チャネルアクセストークン（長期）」→ 発行 | 店舗設定「LINE チャネルアクセストークン」。当選カードの push 通知・後日抽選に必須 |

### LIFF を新しく作る場合

1. LINE ログインチャネル → 「LIFF」タブ → 「追加」
2. LIFF アプリ名: 例「抽選フォーム」
3. サイズ: **Full**
4. エンドポイント URL: いったん `https://form-management-staging.vercel.app` を入れる（あとでフォームの URL に差し替える）
5. Scope: **profile** と **openid** に必ずチェック（ID トークンの取得に必要）
6. 「友だち追加オプション」: **On (aggressive)** にすると友だち追加を促せる
7. 追加すると LIFF ID が表示される

> ⚠️ **チャネル ID について**: すでに予約フォームで使っている LIFF と同じ LINE ログインチャネルなら、環境変数 `NEXT_PUBLIC_LINE_CHANNEL_ID` に入っている値と同じなので店舗設定は空欄で構いません。店舗が**自分の LINE 公式アカウント（別チャネル）**で LIFF を作る場合だけ、店舗設定にそのチャネル ID を入れてください。

## ステップ 5: 管理画面で店舗設定と抽選フォームを作る

### 5-1. 店舗設定（テナント管理画面）

1. https://form-management-staging.vercel.app/tenant/{テナントの slug}/admin を開いてログイン
2. 対象の店舗 → 右上の「店舗情報を編集」
3. 「LINE チャネルアクセストークン」にステップ 4 のトークンを貼る
4. 別チャネルの場合だけ「LINE ログインチャネル ID」を入れる
5. 保存

### 5-2. 抽選フォームを作る

1. 店舗ページの **「抽選フォーム」タブ**（概要 / 予約フォーム / アンケート / 抽選フォーム / 設定 の 4 番目）
2. 「新規抽選フォーム作成」→ フォーム名を入れて、まずは **即時抽選** を選ぶ → LIFF ID を貼る → 作成
3. 自動で編集画面が開くので、タブごとに設定する

| タブ | 最低限やること |
|---|---|
| 基本情報 | タイトル、テーマカラー、受付期間（任意）、引換方式（コード / QR） |
| 賞品と確率 | 賞品名・当選確率（%）・在庫。**確率の合計が 100 を超えると赤く表示され保存できません** |
| 参加条件 | 1 人 1 回 / 1 日 1 回 / 期間中 N 回。事前質問は任意 |
| 演出 | スクラッチ / ガチャ / シンプル |
| メッセージ | 当選・はずれの文言。「Bot から当選カードを push する」に ✓ |

4. 「プレビュー」で見た目と演出を確認（プレビューでは抽選は記録されません）
5. 「保存」→ 問題なければ **「更新」**（これがデプロイ。静的 HTML が Storage にアップロードされます）
6. 一覧カードの **公開ステータス**を「公開中」にする（編集画面の基本情報 → 公開状態、または保存時の status）
7. 一覧カードに出る **フォーム URL** をコピー

### 5-3. LIFF のエンドポイント URL を差し替える

LINE Developers の LIFF 設定を開き、エンドポイント URL を 5-2 でコピーしたフォーム URL（`https://form-management-staging.vercel.app/api/public-form/lotteries/{店舗ID}/{フォームID}/index.html`）に変更して保存。

### 5-4. 公式 LINE に置く

LINE Official Account Manager でリッチメニューやあいさつメッセージに、一覧カードの「公式LINE設定用URL」（`https://liff.line.me/{LIFF ID}`）を設定します。

## ステップ 6: 実機の LINE で動作確認

自分のスマホの LINE で、公式アカウントのリッチメニューから抽選フォームを開いて確認します。

| # | 確認すること | OK の状態 |
|---|---|---|
| 1 | フォームが開く | タイトル・賞品カード・「抽選する」ボタンが表示される |
| 2 | 抽選する | 演出（スクラッチなら指で削れる）→ 結果画面が出る |
| 3 | 「LINE に結果を送る」 | トークに結果テキストが届き、画面が閉じる |
| 4 | 当選時の push | Bot から当選カード（Flex メッセージ）が届く（メッセージタブで push に ✓ した場合） |
| 5 | もう一度開く | 「前回の結果」が表示され、二重に引けない（1 人 1 回のとき） |
| 6 | 管理画面の抽選履歴 | 店舗管理者ページ → 抽選管理 に自分の参加が出る。当選なら「引換」ボタンが押せる |
| 7 | QR 方式のとき | 店舗管理者ページ → 抽選管理 →「QR をスキャン」→ カメラで当選画面の QR を読むと当選内容が出て「引換済みにする」が押せる |
| 8 | パソコンのブラウザで開く | 「公式LINEから開いてください」の画面になり抽選できない |

すべて OK なら staging での確認完了です。

### 後日抽選も使う場合

1. 「後日抽選」でフォームを作る（チャネルアクセストークンが未設定だと作成できません）
2. 基本情報で **応募締切日時**（必須）と抽選予定日を設定、賞品には**当選数**を入れる
3. 公開して、テスト用に 2〜3 人で応募する
4. 抽選フォームタブの下に出る **「後日抽選の管理」パネル**で
   「締め切って抽選する」→ 仮当選を確認（外す / 応募者から追加ができる）→ 「当選を確定して LINE で通知」
5. 当選者の LINE に当選カードが届き、落選者がフォームを開き直すと「はずれ」表示になる

## ステップ 7: 本番へ

staging で問題がなければ、本番も同じ手順です。

1. GitHub で PR を作る: **base `main` ← compare `staging`** → マージ（Vercel が本番を自動デプロイ）
2. **本番の Supabase プロジェクト**で、ステップ 3 と同じ 2 本のマイグレーションを SQL Editor で実行
3. 本番の LINE Developers で LIFF を作り（エンドポイント URL は `https://nas-rsv.com/...`）、店舗設定にトークンを入れる
4. ステップ 5〜6 を本番で実施（テスト用のフォームは確認後に削除してよい）

> ⚠️ `main` への force push は禁止です。本番のマイグレーションは営業時間外に行うと安心です。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 管理画面で「抽選フォームの取得に失敗しました」 | マイグレーション未適用。ステップ 3 を実行 |
| フォームを開くと「準備中です」 | LIFF ID が未設定。編集画面の基本情報で設定して「更新」 |
| 「LINE の認証に失敗しました」 | ① LIFF の Scope に `openid` がない ② 店舗設定のチャネル ID が LIFF のチャネルと違う ③ 環境変数 `NEXT_PUBLIC_LINE_CHANNEL_ID` が未設定。LINE ログインチャネルの「チャネル ID」を店舗設定に入れて再確認 |
| 当選したのに Bot からカードが来ない | ① メッセージタブの「Bot から当選カードを push する」が OFF ② チャネルアクセストークンが未設定・別チャネルのもの ③ お客様が公式アカウントをブロック中。管理画面の抽選履歴で `push` 状態は見えないため、Vercel のログに `[line-push] push failed` が出ていないか確認 |
| 「後日抽選を作成するには…トークンの設定が必要です」 | 店舗設定でチャネルアクセストークンを保存してから作成 |
| QR スキャン画面でカメラが起動しない | iPhone は Safari 17 以降、Android は Chrome で開く。それ以外は 6 桁コードを手入力 |
| 「更新」でデプロイに失敗する | 編集画面の上部に赤いエラー一覧が出ていないか確認（確率合計 100 超過、タイトル未入力、後日抽選の締切未設定 など） |
| 確率を変えたのにフォームに反映されない | 「保存」だけでは公開 HTML は変わりません。**「更新」**を押す |
