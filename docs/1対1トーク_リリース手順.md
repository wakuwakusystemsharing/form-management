# 1 対 1 トーク リリース手順

お客様が公式 LINE に送ったメッセージを管理画面で読み、返信する機能のリリース手順です。
設計は `docs/店舗管理者ページ_追加4機能_実装設計.md` の 8 章にあります。5 回に分けて作ります。

| 回 | 内容 | 状態 |
|---|---|---|
| ④-1 | 受信と保存、ON / OFF と保存期間の設定（運営だけ） | 実装済み |
| ④-2 | トーク画面（一覧・会話・顧客情報）、文字の返信、未読バッジ | 実装済み |
| ④-3 | 通知（スタッフの LINE・メール）、自動削除 | 実装済み |
| ④-4 | 画像の受信と返信、定型文、対応済みの切り替え | 実装済み |
| ④-5 | 自動で送ったメッセージを会話に出す、利用量の記録 | 実装済み |

## 1. マイグレーション（staging / production の両方）

Supabase Dashboard → SQL Editor で実行します。

| 順番 | ファイル | 内容 | いつから必要か |
|---|---|---|---|
| 1 | `supabase/migrations/20261127000000_add_chat.sql` | 設定（`chat_settings`）・会話（`chat_threads`）・メッセージ（`chat_messages`）と、保存の DB 関数 | ④-1 から |
| 2 | `supabase/migrations/20261128000000_add_chat_notifications.sql` | 通知の設定の列と、通知の送りすぎ防止・自動削除の DB 関数 | ④-3 から |
| 3 | `supabase/migrations/20261129000000_add_chat_media.sql` | 定型文の列と、お客様から届いた画像の置き場（公開しないバケツ `chat-media`） | ④-4 から |
| 4 | `supabase/migrations/20261130000000_add_chat_events_usage.sql` | 利用量の表（`chat_usage_monthly`）と、自動で送ったメッセージを会話に残す DB 関数。受信を保存する DB 関数も、利用量を数えるものに差し替える | ④-5 から |

- 適用していなくても、既存の機能（LINE の自動応答など）は今までどおり動きます
- 1 が未適用のあいだは、設定カードに「マイグレーションがまだ適用されていません」と出て、ON にできません
- 2 が未適用でも、受信・トーク画面・返信は動きます。通知の設定を保存しようとすると「マイグレーションがまだ適用されていません」と出ます
- 3 が未適用でも、受信・トーク画面・返信・通知は動きます。定型文を保存しようとすると「マイグレーションがまだ適用されていません」と出ます。画像の置き場は、最初の画像が届いたときに自動で作ります（公開しない設定で作ります）

- 4 が未適用でも、受信・トーク画面・返信・通知・画像は動きます。リマインダー・フォロー・配信も今までどおり送られます。自動で送ったメッセージが会話に出ない・利用量が数えられないだけです

## 1-1. Edge Function の再デプロイ（④-5 から。staging / production の両方）

自動で送ったメッセージを会話に出すために、送信の Edge Function 3 本に「送れたあとで、会話に 1 行を残す」処理を足しました。
**送信そのものの動き（だれに・いつ・何を送るか）は変えていません。**

**先に、上の 4 の SQL を実行してから**、3 本を再デプロイします（順番が逆でも送信は止まりませんが、会話に出るのは両方が済んでからです）。

```bash
supabase functions deploy send-reminders --project-ref <プロジェクト ID>
supabase functions deploy send-follow-messages --project-ref <プロジェクト ID>
supabase functions deploy send-broadcasts --project-ref <プロジェクト ID>
```

- プロジェクト ID: staging = `ohplaysshllkinaiqksb` / production = `tpuqjpdaasxfwsvjcbum`
- **確認**: Dashboard → Edge Functions で、3 本の「Last updated」が今の日時になっている
- 再デプロイしなくても、リマインダー・フォロー・配信は今までどおり送られます（会話に出ないだけです）
- 再デプロイのあと、次のリマインダー（10 分おき）・配信（5 分おき）の実行で、Dashboard → Edge Functions → Logs にエラーが出ていないことを見ます

## 1-2. 自動削除の登録（production だけ）

保存期間（1 年 / 2 年 / 3 年）を過ぎた会話を、1 日 1 回消します。
**登録するまで、会話は消えません。** 保存期間は最短 1 年なので、最初の会話から 1 年たつまでに登録すれば足ります。

本番の Supabase Dashboard → SQL Editor で実行します（`<SERVICE_ROLE_KEY>` は本番プロジェクトの Service Role Key）。
**マイグレーションには含めていません**（テンプレの URL・仮のキーがそのまま登録される事故を防ぐため）。

```sql
select cron.unschedule('run_chat_retention');  -- 既に登録済みなら削除（無ければエラーになるが無視してよい）

select cron.schedule(
  'run_chat_retention',
  '30 19 * * *',   -- 毎日 04:30（日本時間）。UTC で書くので 19:30
  $$
    select net.http_post(
      url := 'https://nas-rsv.com/api/cron/chat-retention',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer <SERVICE_ROLE_KEY>'
      ),
      timeout_milliseconds := 30000
    );
  $$
);
```

- 登録の確認: `select jobname, schedule, active from cron.job where jobname = 'run_chat_retention';`
- 実行の確認: `select status, return_message, start_time from cron.job_run_details where jobid = (select jobid from cron.job where jobname = 'run_chat_retention') order by start_time desc limit 5;`
- 1 回に消すのは 5000 通までです。残りは次の日に消します
- **消した会話は元に戻せません**
- トーク機能を OFF にした店舗の会話も、保存期間を過ぎたら消えます

**staging は登録しません。** staging の Vercel はログイン保護（Deployment Protection）で、cron から呼べません。

## 2. 店舗ごとの準備

**既定は OFF です。ON にした店舗だけ、メッセージを保存します。**

| 順番 | やること | だれが | どこで |
|---|---|---|---|
| 1 | チャネルシークレットの登録 →「接続を確認」 | 運営 | テナント側の店舗ページ → 設定 →「LINE 通知の署名チェック」 |
| 2 | プライバシーポリシーの公開と、店舗からお客様への説明 | 運営・店舗 | `docs/1対1トーク_規約追記の下書き.md` |
| 3 | トーク機能を ON にする | 運営 | テナント側の店舗ページ → 設定 →「1 対 1 トーク」 |

- 1 が済んでいない店舗は ON にできません（偽の通知を会話として保存しないためです）
- 2 が済むまでは、弊社のテスト用店舗（本番の店舗 ID `l9ksjl`）だけ ON にします
- 店舗管理者は、ON / OFF も保存期間も変えられません（API でも断ります）

## 3. 確認（④-1。本番のテスト用店舗 `l9ksjl` で）

staging には LINE からの通知が届かないので（ログイン保護のため）、受信は本番で確かめます。
④-1 には会話を読む画面がまだ無いので、**設定カードの「保存している会話」の件数**で確かめます。

1. 設定 →「LINE 通知の署名チェック」が「登録済み」になっている（未登録なら登録して「接続を確認」）
2. 設定 →「1 対 1 トーク」→「トーク機能を ON にする」→「ON にする」
3. 自分の LINE から、その店舗の公式 LINE に「テストです」と送る
4. 「件数を更新」を押す →「1 人・1 通」になり、最後に届いた日時が出る
5. 続けて「予約確認」と送る →「1 人・2 通」になる（予約確認の返信は今までどおり届く）
6. 画像やスタンプを送る → 通数が増える
7. 「トーク機能を OFF にする」→ もう 1 通送る → 件数が増えない

中身まで確かめたいときは、SQL Editor で次を実行します（テスト用店舗の ID に置き換え）。

```sql
select m.created_at, m.direction, m.kind, m.auto, m.auto_kind, left(m.text, 40) as text
from chat_messages m
where m.store_id = 'l9ksjl'
order by m.created_at desc, m.id desc
limit 20;

select line_user_id, customer_id, unread_count, status, last_message_at, last_message_preview
from chat_threads
where store_id = 'l9ksjl';
```

見るところ:

- 手で書いた文は `auto = false`、「予約確認」などのコマンドは `auto = true`（`auto_kind = command`）
- 予約フォームから予約すると、送信文は `auto_kind = form`、続けて届く 2 通目の文は `follow_up`
- `unread_count` は、手で書いた文・画像・スタンプの数だけ増える（自動の文では増えない）

## 3-2. 確認（④-2。本番のテスト用店舗 `l9ksjl` で）

## 3-3. 確認（④-3。本番のテスト用店舗 `l9ksjl` で）

### 新着の通知

通知の設定は、テナント側の店舗ページ → 設定 →「トークの新着の通知」にあります（店舗管理者ページでは、トークのタブが出ている店舗の設定タブに出ます）。

1. 「メールで通知する」にチェック → 自分のメールアドレスを入れて「保存」
2. 「テストの通知を送る」→ メールが届く。本文に「テスト 様から新しいメッセージが届きました」とリンクがあり、リンクを押すとトークの画面が開く
3. 自分の LINE から「テストです」と送る → メールが届く。**メッセージの内容（テストです）は、メールに書かれていない**
4. すぐにもう 1 通送る → メールは届かない（10 分に 1 回まで）
5. 「予約確認」と送る → メールは届かない（自動の文では通知しない）
6. スタッフの LINE でも受け取るとき: 設定の「今日の予約まとめ・月次レポート」の合言葉でスタッフを登録 →「スタッフの LINE に通知する」にチェック → 保存 →「テストの通知を送る」→ スタッフの LINE に届く（**公式 LINE の通数を、スタッフの人数ぶん使います**）

夜間（既定は 22 時〜8 時）に送ったメッセージでは、通知は届きません。確かめるときは、「夜間は通知を送らない」のチェックを外すか、時間帯を変えてください。

### 自動削除

保存期間は最短 1 年なので、消える会話はまだありません。次の 2 つだけ確かめます。

1. 設定 →「1 対 1 トーク」→ 保存期間を 3 年にしてから 1 年に戻す → 「1 年より前の会話は、次の自動削除で削除され、元に戻せません」と確認が出る
2. cron を登録した翌日に、実行の記録が出ている（上の「実行の確認」の SQL。`return_message` に `{"messages":0,"threads":0,"remaining":false}` のような結果は出ません。`status` が `succeeded` なら動いています）

## 3-4. 確認（④-4。本番のテスト用店舗 `l9ksjl` で）

**画像を送ると、公式 LINE の通数を 1 通使います。**

### お客様から届いた画像

1. 自分の LINE から、公式 LINE に写真を 1 枚送る
2. トークの画面 → 15〜30 秒で会話に出る。最初は「画像を読み込んでいます」と出ることがあるので、一覧の更新ボタンを押す → 写真が出る
3. 写真を押す → 別のタブで大きく表示される
4. **その画像の URL を、ログインしていないブラウザ（シークレットウィンドウ）で開く → 画像が出ない**（ログインの画面になるか、エラーになる）

### 画像を送る

1. トークの画面 →「画像を送る」→ スマホで撮った大きな写真を選ぶ
2. 自分の LINE に写真が届く。会話の右側にも写真が出る
3. 一覧の 1 行が「画像を送りました」になる

### 定型文

1. 「定型文」→「定型文を編集」→「定型文を追加」→ 名前と文を入れて「保存」
2. 「定型文」→ いま作った定型文を押す → 入力欄に文が入る → 書き換えて送信できる

### 対応済み

1. 会話の右上の「対応済みにする」を押す → 一覧に「対応済み」と出る
2. 一覧の「対応中」を押す → その会話が消える（対応中の会話だけになる）
3. 自分の LINE からもう 1 通送る → その会話が「対応中」に戻る

## 3-5. 確認（④-5。本番のテスト用店舗 `l9ksjl` で）

### 自動で送ったメッセージが会話に出る

会話のあるお客様（一度でもメッセージをくれた人）にだけ出ます。自分の LINE で、テスト用店舗にメッセージを送ってある状態で確かめます。

1. 自分の LINE から「予約確認」と送る → トークの会話に、小さく薄い「自動」の行（予約確認）と、まんなかに「「…」を自動で返信しました」の行が出る
2. その会話の未読の数（赤い数字）が、自動の行では増えていない
3. 自分あてに配信を 1 通送る（配信タブ → 自分だけを配信先にして送信）→ 5〜10 分後、会話に「配信「…」を送信しました」と出る
4. 翌日以降の予約を入れておく → リマインダーが届いたあと、会話に「リマインダーを送信しました（… のご予約）」と出る
5. **会話の無いお客様に配信しても、トークの一覧に新しい会話が増えない**

### 利用状況

1. マスター管理者でログイン → `/master-admin` →「トーク利用状況」タブ
2. テスト用店舗の行が出て、受信・返信の数が出る（SQL を実行する前の数は 0 です）
3. 自分の LINE から 1 通送る → 画面を開き直す → 受信が 1 増える。「予約確認」と送っても増えない
4. トークから 1 通返信する → 返信が 1 増える
5. 「CSV でダウンロード」→ Excel で開ける
6. システム管理者・店舗管理者では、このタブは見られない（マスター管理者のページ自体に入れません）

## 4. 既存の店舗への影響

- ON にしていない店舗では、何も保存しません（設定を 1 回読むだけです）
- 通知は既定で OFF です。設定を保存するまで、どこにも送りません
- リマインダー・フォロー・配信・LINE の自動応答は、トーク機能を使っていない店舗でも、今までどおり送られます。送れたあとに「会話に残すか」を 1 回だけ確かめにいきますが、トーク機能が OFF の店舗では何も書き込みません
- 「トーク」タブは、チェックを入れた店舗の店舗管理者にだけ出ます。チェックを入れていない店舗の店舗管理者ページは、今までと変わりません（新着の確認もしません）
- 保存は LINE への応答を返したあとに行うので、予約確認などの返信は遅くなりません
- 保存に失敗しても、LINE の自動応答は今までどおり動きます（失敗はログに残ります）

## 5. 問題が起きたとき

| 起きたこと | 対処 |
|---|---|
| ON にできない | 表示された理由を見ます。「チャネルシークレットを登録してください」→ 署名チェックの登録 / 「マイグレーションが…」→ 1 の SQL を実行 |
| 送ったのに件数が増えない | 「LINE 通知の署名チェック」の「接続を確認」を押します。Webhook URL がこの店舗のものになっているか・シークレットが合っているかが分かります |
| すぐに保存を止めたい | 「トーク機能を OFF にする」を押します。保存済みの会話は消えません |
| 返信が「送信できませんでした」になる | 出ている理由を見ます。「今月の通数の上限に達しています」→ 公式 LINE のプランの上限 / 「チャネルアクセストークンを確認してください」→ 店舗の編集でトークンを登録し直す。「もう一度送る」を押しても二重には届きません |
| 店舗管理者に「トーク」が出ない | トーク機能が ON か、「トークを表示」にチェックが入っているかを確かめます（両方必要です） |
| 通知が届かない | ①「テストの通知を送る」で届くか確かめます（届かなければ、メールアドレス・スタッフの登録を見直します）② 夜間（送らない時間帯）ではないか ③ 同じお客様への通知から 10 分たっているか ④ 送ったのが「予約確認」などの自動の文ではないか |
| 通知が多すぎる | 「スタッフの LINE に通知する」を外してメールだけにするか、通知を OFF にします。管理画面の赤い数字は、通知が OFF でも出ます |
| お客様の画像が「画像（読み込めませんでした）」になる | LINE から画像を取得できませんでした（LINE 側の保存期間切れ・通信エラー・10MB を超える画像）。内容は、公式 LINE のアプリで確認します。あとから取り直すことはできません |
| 画像を送れない | 出ている理由を見ます。「JPEG か PNG の画像だけです」→ 別の画像を選ぶ / 「1MB 以下に縮められませんでした」→ 別の画像を選ぶ |
| リマインダーや配信が、会話に出ない | ① そのお客様との会話があるか（一度もメッセージをくれていない人には出ません）② 4 の SQL を実行したか ③ Edge Function 3 本を再デプロイしたか ④ トーク機能が ON か |
| 利用状況の数が 0 のまま | 4 の SQL を実行したかを確かめます。実行する前の数は、さかのぼっては数えられません |
| 会話の名前が「（お名前不明）」になる | LINE の表示名を取れなかったお客様です。お客様がもう一度メッセージを送るか、予約をすると名前が入ります |

## 6. まだ無いもの（④-5 の時点。予定していた 5 回はすべて実装済み）

- 動画・音声・ファイルの中身（保存しません。「動画が送られました」とだけ出します）
