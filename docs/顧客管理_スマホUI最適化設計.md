# 顧客管理（β）スマホ UI 最適化 設計書

作成日: 2026-09-04 / 対象: 店舗管理者ページ `/{storeId}/admin?tab=customers` の顧客管理タブ配下すべて

- 一覧（`CustomerList.tsx`）
- 顧客詳細（`CustomerDetail.tsx`）と、その中の 4 タブ（予約履歴 / 来店履歴 / 抽選履歴 / LINE 情報）
- 分析（`CustomerAnalytics.tsx`）と、その中の 4 タブ（概要 / 顧客属性 / 来店パターン / 売上分析）
- 顧客の追加・編集フォーム（`CustomerForm.tsx`）
- これらを包む `admin/page.tsx` の `customers` タブ部分

対象外: 予約管理・アンケート・抽選・設定の各タブ、PC 表示（PC の見た目は原則変えない）

---

## 1. 方針（結論）

スマホでは **「画面幅を全部使う」「1 画面で判断できる情報を上に集める」「戻る・閉じる・操作するボタンを親指の届く位置に固定する」** の 3 点に絞って作り直します。

| 原則 | 具体的にやること |
|---|---|
| 余白を二重にしない | ページの `p-4` と Card の `p-6` が重なって左右 40px ずつ空いている。スマホでは **外側の Card をやめて画面幅いっぱい**に、内側の余白は 16px に統一 |
| スクロールを減らす | 見出し・説明文・件数などの「読むだけの行」を 1 行にまとめる。統計は横スクロールのカードではなく **2 列グリッド**で一覧できる高さに収める |
| 主要操作は固定 | 一覧の「顧客を追加」、詳細の「編集 / 削除 / 閉じる」、フォームの「保存 / キャンセル」は **画面下部に固定**（下部ナビや safe area と重ならない） |
| 全画面で開く | 顧客詳細と追加フォームは、スマホでは中央の小さなモーダルではなく **全画面（100dvh）** で開き、ヘッダーに閉じるボタンを置く。標準スタイルでも M3E スタイルでも同じ挙動にする |
| 横スクロールを出さない | 来店履歴の `<table>` はスマホではカード表示に切り替える。タブは 4 つでも 1 行に収まる文字サイズにし、収まらないときは横スクロール可能なチップ列にする |
| タップ領域 44px 以上 | 一覧のカード、タブ、ボタン、行タップの領域を 44px 以上に統一 |
| 既存の 2 スタイルを壊さない | 標準 / M3E（`html[data-ui="m3e"]`）の両方で成立するよう、レイアウトは Tailwind のレスポンシブクラスで、装飾は既存の `data-slot` を使う |

## 2. 現状の問題（スマホ幅 375px を基準に確認）

### 2-1. 一覧（`CustomerList`）

| # | 問題 | 原因 |
|---|---|---|
| L1 | 左右に大きな空白。カードの中身が実質 295px 幅しかない | `admin/page.tsx` の `p-4`（16px）→ Card → `CardHeader p-6`（24px）→ さらに内側の `CustomerList` の Card `p-6`（24px）で **左右合計 64px** が余白 |
| L2 | 「顧客管理 / 顧客情報の確認・管理を行います」「顧客一覧 / N 件の顧客が登録されています」と、**見出しが 2 段重なり**、一覧が表示されるまでに約 260px スクロールが必要 | 外側 Card のヘッダー + 一覧 / 分析タブ + 内側 Card のヘッダー |
| L3 | 「顧客を追加」ボタンがヘッダー右上にあり、一覧をスクロールすると見えなくなる | 固定配置になっていない |
| L4 | 検索欄とセグメント選択が縦に 2 段（高さ 96px）。フィルタを使わない人にも常に表示される | `flex-col` で並べているだけ |
| L5 | 顧客カードの 3 列統計（来店回数 / 総利用金額 / 最終来店日）が 11px と小さく、金額が折り返す | `grid-cols-3` + `text-xs` |

| L7 | 50 件を超えると表示されない（ページングも「もっと見る」もない） | `limit=50` 固定 |

## 3. 設計

### 3-1. 画面の骨格（スマホ）

```
┌──────────────────────────────┐
│ ☰  店舗名                     │  ← 既存のモバイルヘッダー（変更なし）
├──────────────────────────────┤
│ [ 一覧 ]  [ 分析 ]     128 件  │  ← セグメント切替 + 件数（1 行・高さ 44px）
│ 🔍 顧客名、電話番号、メールで検索 ⊗ │  ← 検索（高さ 48px）
│ すべて ▾ 新規 リピーター VIP 休眠 │  ← セグメントのチップ列（横スクロール可・高さ 36px）
├──────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ ◯ 山田 太郎        [VIP] │ │  ← 顧客カード（画面幅いっぱい・余白 16px）
│ │   090-1234-5678          │ │
│ │   来店 12回 ・ ¥86,000 ・ 9/1 │ │  ← 統計は 1 行にまとめる
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ...                      │ │
│                              │
│                    ┌───────┐ │
│                    │ ＋ 追加 │ │  ← 固定ボタン（右下・下部ナビの上）
│                    └───────┘ │
├──────────────────────────────┤
│ 🏠  📅  👥  📋  🎯  ⚙️        │  ← 既存の下部ナビ（変更なし）
└──────────────────────────────┘
```

- 外側の「顧客管理」Card と、内側の「顧客一覧」Card は**スマホでは描画しない**（`md:` 以上でのみ従来の Card）。ページの左右余白は 16px（`px-4`）だけ
- 「一覧 / 分析」の切替は既存の Tabs のまま、`TabsList` を横幅いっぱい・高さ 44px にし、右端に件数を置く
- 検索は共通の `SearchBar`（クリアボタン付き）に置き換え、`useDebounce`（300ms）で API 呼び出しを間引く
- セグメント絞り込みは `Select` ではなく**横スクロールのチップ列**（すべて / 新規 / リピーター / VIP / 休眠）。1 タップで切り替わり、選択中はテーマ色。PC では従来の `Select` を維持
- 顧客カードの統計は「来店 12回 ・ ¥86,000 ・ 最終 9/1」の 1 行（`text-sm`、`tabular-nums`）。名前は 16px、電話は 14px
- 「顧客を追加」は右下の固定ボタン（`position: fixed`、下部ナビ 56px + safe area の上、右 16px）。高さ 48px、ラベル「＋ 追加」。PC では従来どおりヘッダー右上
- 一覧が 50 件を超えたら末尾に「さらに読み込む」ボタン（`offset` を 50 ずつ進める）。ローディング中はカード形のスケルトンを 5 枚出して高さを保つ

### 3-2. 顧客詳細（全画面シート）

```
┌──────────────────────────────┐
│ ‹ 戻る     顧客詳細      ⋯     │  ← 固定ヘッダー 56px。左: 閉じる、右: メニュー（編集 / 削除）
├──────────────────────────────┤
│  ◯  山田 太郎          [VIP]  │  ← アバター 56px + 名前 18px + セグメント
│      ヤマダ タロウ             │
│  📞 090-1234-5678   ✉ a@b.c   │  ← タップで発信 / メール（tel: / mailto:）
│  🎂 1990/01/01  ・ 女性        │
├──────────────────────────────┤
│  来店 12回 │ ¥86,000 │ 初回 2025/1/5 │ 最終 2026/9/1 │  ← 統計 4 つを 2×2、高さ 88px
├──────────────────────────────┤
│ 予約(8)  来店(12)  抽選(2)  LINE │  ← タブ（件数付き・横スクロール可）
│ ┌──────────────────────────┐ │
│ │ 9/10 10:00  カット＆カラー │ │
│ │ [確認済み]              ›  │ │
│ └──────────────────────────┘ │
│ ...                          │
│  メモ                         │
│  ...                         │
└──────────────────────────────┘
```

- スマホでは `DialogContent` を **全画面（inset 0、100dvh、角丸なし、padding 0）** にする。M3E だけでなく標準スタイルでも同じにするため、`CustomerDetail` 側で `className` を付けて制御する（`globals.css` の M3E 専用ルールに依存しない）
- ヘッダーは `position: sticky; top: 0` で常に見える。左に「‹ 戻る」（閉じる）、右に「⋯」メニュー（編集 / 削除）。既定の右上 × は `sr-only` 相当に隠す（`DialogContent` の × は残るため、ヘッダーの高さ内に収めて重ならないよう位置を調整）
- 基本情報・統計・タブは**独立した Card にせず**、区切り線（`border-b`）で分けた 1 枚のシートにする。余白は上下 16px、左右 16px
- 電話とメールは `tel:` / `mailto:` リンクにして、その場で発信・送信できる
- 統計 4 つは 2 列 × 2 行（`grid-cols-2`）。数字は 20px、ラベルは 12px。金額は `tabular-nums`
- タブは件数付き（「予約 (8)」）にして、開く前に中身があるか分かるようにする。4 つが収まらない幅では横スクロール（`overflow-x-auto`、`snap`）
- 来店履歴はスマホでは `<table>` をやめ、「日時 / メニュー / 金額」を 2 行のカードに。PC では従来のテーブル
- 予約履歴の「タップして予約詳細を開く」の行を削除し、カード右端に「›」を出す
- 編集モードは同じシート内で `CustomerForm` に切り替え、ヘッダーのタイトルを「顧客を編集」、左ボタンを「キャンセル」にする。フォーム末尾のボタンは出さず、**下部固定バー**の「保存」に統一
- 削除の確認は `AlertDialog` のまま、スマホではボタンを縦積み・高さ 48px にする（`AlertDialogFooter` の既定は `flex-col-reverse` なので OK。ボタンに `h-12 sm:h-10` を付ける）

### 3-3. 分析

```
┌──────────────────────────────┐
│ [ 一覧 ]  [ 分析 ]             │
│ 概要  顧客属性  来店パターン  売上 │  ← チップ列（横スクロール可）
├──────────────────────────────┤
│ ┌────────┐ ┌────────┐         │
│ │ 総顧客  │ │ VIP    │         │  ← 統計 2×2、1 枚 高さ 72px
│ │  128   │ │  12    │         │
│ └────────┘ └────────┘         │
│ ┌────────┐ ┌────────┐         │
│ │ 新規   │ │ 休眠   │         │
│ └────────┘ └────────┘         │
│ セグメント分布                 │  ← 見出しは 1 行、Card の余白は 16px
│ 新規 ▇▇▇▇▇▇▇▇▇▇ 24            │
│ リピーター ▇▇▇▇▇▇ 68           │
│ ...                          │
└──────────────────────────────┘
```

- 統計カードは**スマホでも 2 列**（`grid-cols-2`）。`CardHeader` + `CardContent` の 2 段をやめ、1 つの `div` に「ラベル（12px）+ 数字（22px）」を縦に置く（`p-4`）
- 分析内の 4 タブは横スクロール可能なチップ列（一覧のセグメントチップと同じ部品）。「売上分析」は「売上」に短縮
- 横棒グラフは「ラベル行」と「バー + 数値」を分け、ラベルが長くても数値が押し出されないようにする（`grid-cols-[1fr_auto]`）。バーの高さを 8px → 10px
- 売上ランキングの行はタップで顧客詳細を開けるようにする（`onCustomerClick` を props で受け取る。無ければ従来どおり）
- 「来店パターン」の 3 枚（平均来店間隔 / リピート率 / リピーター数）は 1 列縦積みでなく、スマホでは 3 枚を**横 3 列**（数字 22px）に収める
- 各 Card の余白はスマホ 16px（`p-4`）、PC 24px（`p-6`）

### 3-4. 追加・編集フォーム

- 追加はスマホでは**全画面シート**（詳細と同じ部品）。ヘッダー「新規顧客を追加」、左「キャンセル」、下部固定バー「追加」
- 項目の並び（スマホ）: 顧客名 / フリガナ / 電話番号 / メール / 誕生日・性別（2 列）/ 顧客タイプ / メモ。`sm:grid-cols-3` を `grid-cols-2 sm:grid-cols-3` に
- アバター行は「編集」かつ LINE 画像があるときだけ表示。新規追加では出さない
- 顧客タイプの注記は 1 行に短縮し、詳しい説明は `title` 属性（PC のツールチップ）に逃がす
- 入力欄は既存のとおり 16px（iOS のズーム防止）。`enterKeyHint`（次へ / 完了）を付ける
- 下部固定バーはキーボード表示時に隠れないよう、`position: sticky; bottom: 0` をフォームの末尾に置く（`fixed` だと iOS でキーボード上に浮くため）

### 3-5. 共通部品（新規）

| 部品 | 役割 |
|---|---|
| `MobileSheet`（`CustomerDetail` / 追加フォームで共用） | スマホでは全画面、PC では従来のダイアログ。固定ヘッダー（左ボタン / タイトル / 右ボタン）と下部固定バーのスロットを持つ。`Dialog` をラップするだけでロジックは持たない |
| `ChipTabs` | 横スクロール可能なチップ列。`Tabs` の `TabsList` に `overflow-x-auto`、`TabsTrigger` に `shrink-0` を付けた薄いラッパー。件数バッジを表示できる |
| `StatTile` | 「ラベル + 数字」の小カード。詳細と分析で共用 |
| `ListSkeleton` | 一覧ローディング用のスケルトン（5 枚） |

いずれも `src/components/customers/` 配下に置き、他タブへの影響を避ける。

### 3-6. スタイルの扱い（標準 / M3E）

- レイアウト（幅・余白・固定配置・列数）は Tailwind のレスポンシブクラスで書き、**両スタイルで共通**
- 装飾（角丸・色・影）は既存の `data-slot`（`card` / `list-item` / `tabs-list` / `tabs-trigger` / `dialog-content` / `button`）に任せる
- M3E の `dialog-content` 全画面ルールは、`CustomerDetail` 側でも同じ結果になるため衝突しない（両方が `inset: 0` を指定）。ただし M3E 側の `padding-top: 1.5rem + safe-area` は固定ヘッダーと二重になるため、**顧客管理のシートには `data-slot="mobile-sheet"` を付けて、M3E 側の padding を 0 に上書き**する（`globals.css` に 1 ルール追加）

## 4-2. 実装状況（2026-09-04）

実装済み。設計からの差分は次のとおり。

- 共通部品は `src/components/customers/`（`MobileSheet` / `ChipTabs`（`ChipTabsList` + `ChipFilter`）/ `StatTile`（+ `StatGrid`）/ `ListSkeleton`）
- 全画面シートの高さは `100dvh` 固定ではなく `top: 0; bottom: 0` の両端固定にした（headless Chrome で下に隙間が出たため。実機のブラウザ UI の出入りにも追従する）
- M3E スタイルとの整合は `globals.css` に `mobile-sheet` / `mobile-sheet-header` / `mobile-sheet-footer` / `fab` / `status-chip[data-active]` の 5 ルールを追加
- 追加で `?tab=customers&customerId=...` のディープリンクで顧客詳細を直接開けるようにした（抽選履歴の「顧客情報を見る」リンクが機能していなかったため）
- 分析の売上ランキングは行タップで顧客詳細を開く
- 検証は Chrome ヘッドレス（幅 500px。Chrome の最小ウィンドウ幅のため 390px では右端が切れる。スマホ判定は 768px 未満なので同じレイアウト）で一覧 / 分析 / 詳細 / 追加フォームを標準・M3E の両スタイルで撮影して確認。実機での確認（キーボード表示時の固定バー、`tel:` / `mailto:`、safe area）は staging で行う

## 5. 検証方法

実機（iPhone / Android）の LINE 外ブラウザと、Chrome の端末エミュレーション（375×667、390×844、414×896）で確認します。

| # | 確認項目 | 合格条件 |
|---|---|---|
| 1 | 一覧の左右余白 | カードの左右が画面端から 16px。横スクロールが出ない |
| 2 | 一覧の最初のカードまでの距離 | ヘッダー下から 140px 以内（切替 44 + 検索 48 + チップ 36 + 余白） |
| 3 | 「追加」ボタン | 一覧をどこまでスクロールしても右下に見える。下部ナビと重ならない |
| 4 | 検索 | 入力中に一覧がちらつかない（300ms 後に更新）。× で即クリア |
| 5 | セグメントチップ | 1 タップで切り替わり、選択中が分かる。5 つが収まらない幅では横スクロール |
| 6 | 詳細を開く | 全画面で開き、ヘッダーの「‹ 戻る」で閉じる。標準 / M3E の両スタイルで同じ |
| 7 | 詳細の統計 | 4 つが 1 画面に収まる（2×2） |
| 8 | 来店履歴 | テーブルでなくカード。横スクロールなし |
| 9 | 電話 / メール | タップで発信 / メール作成が開く |
| 10 | 編集 | 下部固定バーの「保存」で更新でき、キーボード表示中もバーが押せる |
| 11 | 削除 | 確認ダイアログのボタンが 48px、縦積み |
| 12 | 分析の統計 | 4 枚が 2×2 で 1 画面に収まる。来店パターンの 3 枚が横並び |
| 13 | 分析のタブ | 4 つが折り返さない。収まらなければ横スクロール |
| 14 | 追加フォーム | 全画面。誕生日と性別が 2 列。「追加」が下部固定バー |
| 15 | PC | 1024px 以上で従来と同じ見た目（Card・テーブル・ヘッダー右上のボタン） |
| 16 | 自動テスト | `pnpm type-check` / ESLint / Vitest / `next build` が通る |
