# リッチメニュー リリース手順

公式 LINE のトーク画面の下に出るメニュー（リッチメニュー）を、管理画面で作って反映する機能のリリース手順です。
設計は `docs/店舗管理者ページ_追加4機能_実装設計.md` の 7 章にあります。

## 1. マイグレーション（staging / production の両方）

Supabase Dashboard → SQL Editor で、次の 2 つを**上から順に**実行します。

| 順番 | ファイル | 内容 | いつから必要か |
|---|---|---|---|
| 1 | `supabase/migrations/20261125000000_add_line_rich_menus.sql` | メニューの保存先（`line_rich_menus`） | 1 回目（作成と反映）から |
| 2 | `supabase/migrations/20261126000000_add_line_rich_menu_links.sql` | お客様ごとの切り替えの記録（`line_rich_menu_links`） | 3 回目（お客様ごとの切り替え）から |

- 適用していなくても、既存の機能は今までどおり動きます
- 1 が未適用: リッチメニューの一覧が空になり、作成すると「マイグレーションがまだ適用されていません」と出ます
- 2 が未適用: 全員向けのメニューとタブ切り替えは使えます。お客様ごとのメニューを出そうとすると「マイグレーションがまだ適用されていません」と出ます

## 2. 1 日 1 回の見直し（production だけ）

お客様ごとのメニューは、予約が入ったとき・顧客情報を変えたときに自動で見直しますが、
日がたつと変わる条件（最終来店から ◯ 日・誕生月など）と、アンケートなどで付いたタグは、1 日 1 回の見直しで拾います。

本番の Supabase Dashboard → SQL Editor で実行します（`<SERVICE_ROLE_KEY>` は本番プロジェクトの Service Role Key）。
**マイグレーションには含めていません**（テンプレの URL・仮のキーがそのまま登録される事故を防ぐため）。

```sql
select cron.unschedule('run_rich_menu_sync');  -- 既に登録済みなら削除（無ければエラーになるが無視してよい）

select cron.schedule(
  'run_rich_menu_sync',
  '15 19 * * *',   -- 毎日 04:15（日本時間）。UTC で書くので 19:15
  $$
    select net.http_post(
      url := 'https://nas-rsv.com/api/cron/rich-menu-sync',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer <SERVICE_ROLE_KEY>'
      ),
      timeout_milliseconds := 30000
    );
  $$
);
```

- 登録の確認: `select jobname, schedule, active from cron.job where jobname = 'run_rich_menu_sync';`
- 実行の確認: `select status, return_message, start_time from cron.job_run_details where jobid = (select jobid from cron.job where jobname = 'run_rich_menu_sync') order by start_time desc limit 5;`
- お客様ごとのメニューを出している店舗が無いあいだは、何もしません
- 1 回で終わらなかったぶん（22 秒で切り上げ）は、次の回に続きを行います。急ぐときは、画面の「いま見直す」を押します

**staging は登録しません。** staging の Vercel はログイン保護（Deployment Protection）で、cron から呼べません。
staging では、画面の「いま見直す」で確認します。

## 3. 店舗ごとの準備

| やること | だれが | どこで |
|---|---|---|
| LINE のチャネルアクセストークンの登録 | 運営 | テナント側の店舗ページ → 店舗の編集（リマインダーなどで登録済みなら不要） |
| 店舗管理者にタブを見せる（任意） | 運営 | テナント側の店舗ページ → 設定 →「店舗管理者に表示するメニュー」→「リッチメニューを表示」。既定は非表示 |
| チャネルシークレットの登録（**お客様ごとの切り替えを使う店舗だけ**） | 運営 | テナント側の店舗ページ → 設定 →「LINE 通知の署名チェック」 |

## 4. 確認（本番のデモ店舗で）

「反映する」「条件に合うお客様に出す」を押すと、その店舗の公式 LINE のメニューが本当に変わります。**デモ用の公式 LINE がつながった店舗で確認してください。**

### 全員向けのメニュー

1. 作成 → 画像の切り抜き → 型を選ぶ → ボタンの動き → 保存
2. 「反映する」→ 実機にメニューが出て、ボタンが正しい位置で動く
3. 内容を変えて保存 →「もう一度反映する」→ 実機のメニューが変わる（途中でメニューが消えない）
4. 「反映をやめる」→ 公式 LINE の管理画面で設定したメニューに戻る

### タブ切り替え

1. メニュー A と B を作り、互いに切り替えるボタンにして A を反映
2. 実機で A が出て、ボタンで B に切り替わり、B から A に戻れる
3. B に切り替えた状態のまま A を「もう一度反映する」→ トークを開き直して、メニューがどう見えるかを確かめる

### お客様ごとの切り替え

1. デモ店舗にチャネルシークレットを登録する
2. 自分の LINE のお客様（顧客管理）に、確認用のタグ（例: `確認用`）を付ける
3. 「条件に合うお客様だけ」→ タグ `確認用` のメニューを作って「条件に合うお客様に出す」→ 自分の実機だけ、そのメニューに変わる（「いま 1 人に設定中」）
4. タグを外す → 少し待つか「いま見直す」→ 実機が全員向けのメニューに戻る
5. 「出すのをやめる」→ 実機が全員向けのメニューに戻る

メニューの変更が実機に出るまで、少し時間がかかることがあります（LINE 側の反映待ち。トークを開き直すと出ます）。

## 5. 問題が起きたとき

| 起きたこと | 対処 |
|---|---|
| 反映に失敗した | 一覧に理由が出ます。公式 LINE には、前のメニューがそのまま出ています。「LINE のチャネルアクセストークンを確認してください」と出たら、トークンを登録し直します |
| 「ほかの場所で、全員向けのメニューが変更されています」と出る | 公式 LINE の管理画面や別のツールで変えられています。このシステムのメニューを出すなら、もう一度「反映する」を押します |
| お客様ごとのメニューが、合わないはずの人に出ている | 「いま見直す」を押します。直らないときは「出すのをやめる」を押すと、全員向けのメニューに戻ります |
| すぐに全部やめたい | お客様ごとのメニューは「出すのをやめる」、全員向けのメニューは「反映をやめる」を押します。公式 LINE の管理画面で設定したメニューに戻ります |
