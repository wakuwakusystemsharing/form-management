# 朝の「今日の予約まとめ」・月次レポート 実装設計

毎朝「今日の予約」を、毎月 1 日に「先月の成果」を、店舗スタッフのメール / LINE へ自動で送る。
管理画面には「月次レポート」の画面を新設し、過去の月も見られる。リリース手順は `docs/朝のまとめ・月次レポート_リリース手順.md`。

## 1. 仕様

| 項目 | 内容 |
|---|---|
| 設定する場所 | 店舗管理者ページ → 設定タブ / テナント側 店舗ページ → 設定タブ（同じカード `StoreDigestSettings`）。既定はすべて OFF |
| 送る内容 | 「今日の予約まとめを毎朝送る」「月次レポートを毎月 1 日に送る」を別々に ON / OFF |
| 送る時刻 | 5:00〜12:00 の 1 時間刻み（既定 8:00。JST）。月次レポートも同じ時刻 |
| 送り先 | メール（5 件まで）/ LINE（合言葉で登録したスタッフ。10 人まで）。両方選べる |
| 朝のまとめの中身 | 今日の予約（時刻・お名前・メニュー・担当）、未確認の申し送り、しるし（新規 / VIP / 誕生月）、「注意あり」、今日の日時への空き待ちの件数。**予約が 0 件の日は送らない** |
| 要配慮個人情報 | アレルギー・既往歴は**中身を載せず「注意あり」とだけ**出す（中身は顧客詳細で見る） |
| 月次レポートの中身 | 予約数・売上・1 件あたり・新規のお客様・リピート率・キャンセル率・前月比・人気メニュー（上位 5）・配信の成果 |
| 二重送信の防止 | 送る前に `store_digest_logs` の行（店舗 × 種類 × 対象日 / 月）を確保。回が重なっても 1 回だけ |
| 取りこぼし | 朝のまとめ = 設定時刻から 3 時間以内なら送る（それより遅ければその日は送らない）。月次 = 1〜3 日のあいだに 1 回 |
| テスト送信 | 設定カードのボタン。保存済みの送り先へいまの内容を送る（記録には残さない。予約 0 件でも送る） |

### しるしの決め方（朝のまとめ）

- 新規 … 顧客台帳に無い、または来店 1 回（来店記録は予約成立時に作られるので、今日が初めての人は来店 1 回）
- VIP … 総利用 5 万円以上 または 来店 10 回以上（顧客管理のセグメントと同じ基準）
- 誕生月 … 誕生日の月 = 今日の月
- 注意あり … `customers.allergies` / `medical_history` のどちらかに登録がある

### 月次レポートの数え方（`computeMonthlyReport`）

- 対象 = **予約日がその月**の予約。キャンセルは予約数・売上から除く（予約分析と同じ `computeReservationAnalytics` / `reservationAmount`）
- お客様の特定 = 顧客 ID → LINE ユーザー ID → 電話番号
- 新規のお客様 = その月より前に（キャンセル以外の）予約が無い人 / リピート率 = その月に予約した人のうち、以前にも予約がある人の割合
- キャンセル率 = キャンセル ÷（予約数 + キャンセル）
- 配信の成果 = その月に送った配信ごとに、送信後 7 日以内の予約（`computeBroadcastResult`）を合計
- 集計は保存せず、開いたとき / 送るときに計算する

### LINE のスタッフ登録（合言葉）

1. 設定カードに 4 桁の合言葉が出る（店舗ごと。初めて開いたときに自動で作る）
2. スタッフが公式 LINE に「スタッフ登録 4821」と送る → Webhook が `handleStaffLineCommand` で照合して `store_digest_staff` に登録（表示名は LINE のプロフィールから）
3. 解除 = 「スタッフ登録解除」と送る / 設定カードの一覧の「解除」
4. 合言葉を **5 回間違えると無効**（`staff_code = NULL`）。「合言葉を出し直す」で作り直す（登録済みのスタッフはそのまま）
5. 「スタッフ登録」「スタッフ登録解除」は LINE メッセージのキーワード自動応答・配信停止キーワードに登録できない

LINE で送ると公式 LINE の通数を使う（1 回 × スタッフの人数）。設定カードに注意書きを出す。

## 2. 構成

| 種類 | ファイル |
|---|---|
| 純粋ロジック | `src/lib/store-digest.ts`（設定の正規化・検証 / 合言葉 / 送る時刻の判定 / `buildMorningDigest` / `computeMonthlyReport` / メール本文 / LINE の Flex） |
| 保存 | `src/lib/store-digest-repository.ts`（local は `data/store_digest.json`） |
| サーバー | `src/lib/store-digest-service.ts`（`getDigestState` / `saveDigestSettings` / `reissueStaffCode` / `handleStaffLineCommand` / `runDueDigests` / `sendDigestTest` / `getMonthlyReportPage`） |
| 起動 | pg_cron `run_store_digest`（毎時 0 分。**本番のみ登録**）→ `POST /api/cron/store-digest`（Service Role Key の Bearer。22 秒で切り上げ） |
| API | `GET/PUT /api/stores/{storeId}/digest`、`POST .../digest/staff-code`、`DELETE .../digest/staff/{staffId}`、`POST .../digest/test`、`GET /api/stores/{storeId}/reports/monthly?month=YYYY-MM`（すべて `authorizeStoreAccess`） |
| Webhook | `src/app/api/webhooks/line/route.ts`（「スタッフ登録」で始まる発言を配信停止より先に処理。失敗しても他の応答は止めない） |
| 画面 | `src/components/StoreDigestSettings.tsx`（設定カード）、`src/components/MonthlyReportView.tsx`（月次レポート。`/{storeId}/admin?tab=dashboard&report=YYYY-MM`。ダッシュボードの「月次レポートを見る」から開く） |
| DB | `supabase/migrations/20261120000000_add_store_digest.sql`（`store_digest_settings` / `store_digest_staff` / `store_digest_logs`。RLS ポリシー無し = service_role のみ） |
| テスト | `store-digest.test.ts` / `store-digest-service.local.test.ts` |

メール・LINE のリンク先: 朝のまとめ = `/{storeId}/admin?tab=reservations`、月次 = `/{storeId}/admin?tab=dashboard&report=YYYY-MM`
（未ログインならログイン画面が出て、ログイン後にそのまま開く）。ダッシュボードのタブを非表示にしている店舗管理者は月次レポートの画面を開けない（先頭の表示タブへ移る）。

## 3. 制限・注意

- メールは Resend（`RESEND_API_KEY` / `EMAIL_FROM_ADDRESS`）。未設定の環境では送れない（記録は「失敗」）
- 登録したスタッフも公式 LINE の友だちなので、顧客管理の「LINE 友だちのみ」に入り、配信の宛先にも含まれる
- LINE のカードに載せる予約は 15 件まで（それ以上は「ほか N 件」。メールは全件）
- staging の Vercel はログイン保護のため cron から呼べない。staging は「テスト送信」で確認する
