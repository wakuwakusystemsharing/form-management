# 配信の成果（配信 → 予約数・売上）実装設計

「この配信で予約 12 件・売上 84,000 円」を配信ごとに出す機能。配信タブ → 配信一覧に表示する。

## 1. 何を数えるか

| 数字 | 意味 |
|---|---|
| **タップした人の予約**（主） | 配信のボタンをタップした人が、**タップより後**に受け付けた予約 |
| **受け取った人の予約**（参考値） | 配信を受け取った人（送信済みの宛先）が、送信より後に受け付けた予約すべて。配信と関係なく入った予約も含まれる |

- 期間: 配信（その人への送信時刻）から **3 / 7 / 14 日以内**に受け付けた予約。画面で切り替える（既定 7 日）。基準は予約日ではなく**予約を受け付けた日時**（`reservations.created_at`）
- キャンセル済みの予約は数えない
- 売上は予約分析と同じ（`reservationAmount` = メニュー + オプション + 宿泊料金 + 指名料）
- 予約と宛先の紐付けは 顧客 ID → LINE ユーザー ID の順。店舗が管理画面から入れた予約も、その顧客の予約なら数える
- 同じ予約が 2 つの配信の期間に入るときは、**両方の配信に数える**（配信ごとに独立して集計する。配信の成果の合計は予約の総数と一致しない）
- 期間がまだ終わっていない配信は「集計中」と表示する

## 2. 誰がタップしたかの記録

これまでは計測リンク（`/go/b/{配信ID}/{key}`）でタップの**回数**だけを数えていた。成果を出すには「誰が」が要る。

- 送信用メッセージを作るとき（`buildBroadcastPayloads`）、計測 ON なら計測リンクの末尾に **宛先の印 `?r=__RID__`** を付ける（`tagRecipientLinks`）。対象は このアプリの計測リンクすべて = 配信に直接足した Flex の `/go/b/{配信ID}/{key}` と、保存済み LINE メッセージ（`ref`）の `/go/{メッセージID}/{key}`
- Edge Function `send-broadcasts` が送るときに、印を**宛先の行 ID**（`broadcast_recipients.id`。UUID）に置き換える（`fillRecipientLinks`。TS 版と Deno 版は同じ規則。**直すときは両方**）
- **印のある配信は multicast ではなく 1 人ずつ push で送る**（内容が 1 人ずつ違うため。`{name}` の差し込みがある配信と同じ経路。並列数は 20）。通数の消費は変わらない（1 人 = 1 通）。大人数の配信は送信に少し時間がかかる
- 計測リンクが開かれると、`?r=` があれば `recordBroadcastTap(宛先の行 ID)` → DB 関数 `broadcast_record_tap` が `broadcast_recipients.tapped_at`（最初のタップの日時）と `tap_count` を更新する。従来のタップ数（`broadcasts.tap_counts` / `line_flex_messages.tap_counts`）も今までどおり数える
- テスト送信は宛先の行が無いので印を外して送る（`fillRecipientLinks(payloads, null)`）

### 「タップした人の予約」を出せない配信

`tracked = false`（`payloadsHaveRecipientLinks(b.payloads)` が false）の配信は、受け取った人の予約だけを表示する。

- この機能より前に送った配信
- 計測 OFF（`track_taps = false`）の配信
- ボタン（URL を開くもの）が 1 つも無い配信

集計は保存しない。画面を開いたときに「送信済みの宛先」と「送信後に受け付けた予約」から計算する（期間の切り替え・予約のキャンセルがそのまま反映される）。

## 4. 互換性

- マイグレーション未適用: 配信・タップ数は従来どおり動く。タップした人は記録されず（RPC の失敗はログのみ）、成果は「タップした人の予約 0 件」+ 受け取った人の予約になる
- Edge Function が古いまま: 印が置き換えられず `?r=__RID__` のまま届く。計測リンクは UUID でない `r` を無視するので、リンクは正常に開きタップ数も数える（タップした人だけ記録されない）
- 自動配信（「【自動】…」）も同じ仕組みで成果が出る
