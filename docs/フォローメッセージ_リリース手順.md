## ステップ 4: pg_cron ジョブの登録

Dashboard → SQL Editor で実行（`<SERVICE_ROLE_KEY>` を staging の Service Role Key に置き換える）。
リマインダーは毎時 0 分なので、フォローは**毎時 5 分**にずらしてあります。

```sql
select cron.unschedule('send_follow_messages');  -- 既に登録済みなら削除（無ければエラーになるが無視してよい）

select cron.schedule(
  'send_follow_messages',
  '5 * * * *',
  $$
    select net.http_post(
      url := 'https://ohplaysshllkinaiqksb.supabase.co/functions/v1/send-follow-messages',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer <SERVICE_ROLE_KEY>'
      )
    );
  $$
);
```

**確認:**
```sql
select jobname, schedule from cron.job order by jobname;
-- send_follow_messages       5 * * * *
-- send_reservation_reminders 0 * * * *   ← 変わっていないこと
```

## ステップ 5: 動作確認

### 5-1. 設定
1. テナント管理画面 → 店舗ページ → 概要タブ → 基本情報の「編集」
2. 予約リマインダーの下の「フォローメッセージ」を **有効** にする
3. 基準日「予約日（来店日）から」、何日後「翌日（1日後）」、送信時刻は**今から 1〜2 時間後**、文面は任意 → 保存

### 5-2. 予約 → 予定が作られる
LIFF から LINE ユーザーで予約する（予約日は**今日**にする）。

```sql
select reservation_id, base_date, scheduled_at, status, skip_reason
  from follow_messages order by created_at desc limit 5;
-- status = scheduled、scheduled_at = 明日 HH:00 JST（UTC 表記では -9 時間）
```

> 予定日を待たずに確認したいときは、`update follow_messages set scheduled_at = now() where id = '...'` のあと、ステップ 3 の curl で Function を手動実行してください。

### 5-3. 再予約で差し替わる
同じ LINE ユーザーで**もう 1 件**予約する。

```sql
-- 古い行が superseded、新しい行が scheduled になっている
```

### 5-4. 見送りの確認
- 新しい予約のフォロー送信より前に、そのユーザーに未来の予約が残っている状態で Function を実行 → `skipped` / `rebooked`
- 予約をキャンセル → その行が `cancelled` / `reservation_cancelled`
- 店舗のフォローを OFF にして Function を実行 → `skipped` / `store_disabled`

### 5-5. 実際に届く
5-2 の手順で `scheduled_at` を今にして Function を実行 → LINE に Flex メッセージが届き、行が `sent` になる。
店舗管理画面 → 顧客管理 → 顧客詳細 → 予約履歴に「フォロー送信済み」バッジが出る。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| 予約しても `follow_messages` に行ができない | 店舗の `follow_enabled` が true か / 予約に `line_user_id` があるか（Web 予約・電話番号のみは対象外）/ 予定が過去になっていないか（過去日の手動登録は作らない）/ Vercel のログで `[follow-message]` を検索 |
| `scheduled` のまま送られない | cron が登録されているか（ステップ 4 の確認 SQL）/ Edge Function のログ（Dashboard → Edge Functions → Logs） |
| `failed` になる | `last_error` 列に LINE API の応答が入る。`401` ならチャネルアクセストークン、`400` はユーザーがブロックしている可能性 |
| リマインダーと同じ日に両方届いた | フォロー側は「今日 + reminder_days_before に未キャンセル予約がある」ときだけ見送る。リマインダーが別店舗・別ユーザーの設定で送られていないか確認 |
| 止めたい | 店舗のフォローを OFF にする（未送信行は次回実行時に `store_disabled` で見送られる）。全体を止めるなら `select cron.unschedule('send_follow_messages');` |
