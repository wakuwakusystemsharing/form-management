# 空き待ち（キャンセル待ち）機能 リリース手順

仕様書: `docs/8年11月18日追加機能/waitlist-spec.md`

満席（✕）の時間にお客様が「空き待ち」を登録でき、キャンセルや日時変更でその時間が空くと LINE で自動的にお知らせする機能です。
**機能は初期状態 OFF** です。フォームごとに ON にして「保存＆デプロイ」したフォームだけ動きます。

## 第 1 弾に入っているもの

- フォームごとの ON / OFF、1 人あたりの登録上限、受付締切（営業時間・ルール → 「空き待ち（キャンセル待ち）設定」）
- お客様: 予約カレンダーの ✕ をタップして登録 / 「あなたの空き待ち」の確認・取り消し / LINE で「空き待ち確認」
- 空きのお知らせ（登録者全員・先着順）、埋まったときのおわび（空き待ちは継続）、再び空いたときの再通知
- 日時を過ぎた空き待ちの自動終了
- 店舗: 予約一覧の上の「空き待ち（キャンセル待ち）」（一覧・取り消し・「今すぐ空きを確認」）

## 第 2 弾に入っているもの

- **夜間はお知らせを送らない**（空き待ち設定 → 「夜間はお知らせを送らない」。既定 OFF / 22:00〜8:00）。その時間帯は空きのお知らせ・埋まったお知らせを送らず、明けたあとの見回りで、その時点で空いていれば送ります
- **お知らせの文面の編集**（空き待ち設定 → 「文面を編集」）。受付完了 / 空きのお知らせ / おわび の最初の文章を変更できます。`{日時}` `{メニュー}` `{店名}` `{予約URL}` を差し込めます。日時などの表示・注意書き・予約ボタンは常に表示されます
- **日時ごとの人数**（予約一覧の上の「空き待ち（キャンセル待ち）」→「日時ごとの人数」）
- **送信履歴**と**今月の送信数**（同じ場所の「送信履歴」と、パネル上部の表示。公式 LINE 全体の今月の送信数と上限も表示）

第 2 弾は**データベースの更新・cron の追加は不要**です（第 1 弾のテーブルをそのまま使います）。夜間の設定と文面は、保存するだけで反映されます（再デプロイ不要）。

> 注意: 「夜間はお知らせを送らない」を使う場合、明けたあとのお知らせは **10 分おきの見回り（cron）** が送ります。cron を登録していない環境（staging）では、朝に「今すぐ空きを確認」を押すか、次のキャンセル・予約が入るまで送られません。

## 手順

### 1. データベースの更新（staging / production それぞれ）

Supabase Dashboard → SQL Editor で `supabase/migrations/20261118000000_add_waitlist.sql` の内容を実行します。

- 作られるもの: `waitlist_entries`（空き待ち）/ `waitlist_notifications`（通知の記録）
- 未適用のままでも、予約・キャンセルなど既存の動きには影響しません（空き待ちの登録だけがエラーになります）

### 2. アプリのデプロイ

通常どおり PR をマージします（環境変数の追加・Edge Function の再デプロイは不要）。

### 3. 10 分おきの見回り（cron）の登録 — **本番のみ**

店舗が Google カレンダーの予定を直接消したときの空きを見つけるためと、日時を過ぎた空き待ちを終了するための定期実行です。
本番の Supabase Dashboard → SQL Editor で実行します（`<SERVICE_ROLE_KEY>` は本番プロジェクトの Service Role Key）。

```sql
select cron.unschedule('run_waitlist_check');  -- 既に登録済みなら削除（無ければエラーになるが無視してよい）

select cron.schedule(
  'run_waitlist_check',
  '*/10 * * * *',
  $$
    select net.http_post(
      url := 'https://nas-rsv.com/api/cron/waitlist',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer <SERVICE_ROLE_KEY>'
      ),
      timeout_milliseconds := 30000
    );
  $$
);
```

- cron を登録しなくても、**このシステムでのキャンセル・日時変更・新しい予約の直後**には見回りが動きます（お知らせ・おわびは届きます）
- **staging の Vercel はログイン保護のため cron から呼べません**。staging では、予約一覧の上の「空き待ち（キャンセル待ち）」→「今すぐ空きを確認」で同じ見回りを手動で実行して確認します

### 4. フォームの設定

1. 予約フォームの編集 → 営業時間・ルール → 「空き待ち（キャンセル待ち）設定」→ 「空き待ちを受け付ける」を ON
2. 上限件数・受付締切を選ぶ
3. **保存＆デプロイ**（デプロイするまで、お客様のフォームには出ません）
4. （任意）公式 LINE のリッチメニューに「空き待ち確認」と送るボタンを置く

使えるのは **LINE の予約フォーム × 日時選択モード「Googleカレンダー連携」** だけです（Web 予約フォーム・第三希望日時・宿泊では使えません）。

## 動作確認（staging）

1. フォームで空き待ちを ON → 保存＆デプロイ
2. ある時間を予約で埋める（A さん）
3. 別の LINE アカウント（B さん）でフォームを開き、その時間の ✕ をタップ → 「空き待ちに登録する」
   - トークに「空き待ちを受け付けました」のカードが届く
   - カレンダーのその時間が「待」になる
4. A さんの予約をキャンセル（LINE の「予約をキャンセル」または管理画面）
   - 10 秒ほどで B さんに「空きが出ました」が届く
5. 「この日時で予約する」→ メニューと日時が入った状態でフォームが開く → 予約
   - ほかに空き待ちの人（C さん）がいれば「お知らせした枠は埋まりました」が届く
6. 予約一覧の上の「空き待ち（キャンセル待ち）」に登録と状態が出ていること

## 注意

- 空きのお知らせ・おわびは **LINE の push メッセージ**で、公式 LINE の月間の送信数（通数）を使います。登録の受付カードは返信（無料）です
- お知らせは「送信直前のカレンダー」で空きを確認してから送ります。キャンセル直後は 10 秒待ってから確認します（すぐ取り直された枠を知らせないため）
- カレンダーの予定を取得できなかったときは何も送りません（次の見回りで判断します）
- メニュー / オプションの「対応時間設定」は空きの判定に使いません（「予約を変更」と同じ）
